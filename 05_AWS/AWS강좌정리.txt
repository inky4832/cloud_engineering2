1. 클라우드 컴퓨팅

   1)개념
    IT 리소스 ( 컴퓨팅, 스토리지, 네트워크등)를 사용한만큼만 비용을 지불해서 빌려쓰는 서비스.  
    반대되는 개념이 온프레미스(on-premise, 사용자가 직접 IT리소스를 구입)임.
	
   2)종류
   
      가. IaaS ( Infrastructure as a Service )
	     - IT 리소스의 주요자원인 네트워크, 스토리지, 서버등 포함한 자원을 빌려주는 서비스. 
		   쉽게말해서 노트북을 빌려주는 서비스임.
		 - AWS 관련 주요 서비스: EC2
		 
	  나. PaaS ( Platform as a Service )
	     - OS와 런타임 환경을 빌려주는 서비스 
		 - AWS 관련 주요 서비스: AWS Elastic Beanstalk, firebase 
		 
	  다. SaaS ( Software as a Service )
	    - 어플리케이션을 빌려주는 서비스 
		- 주요 서비스: 구글 docs, gmail, Slack
		  
	https://cloud.google.com/learn/paas-vs-iaas-vs-saas?hl=ko 참조.
	
   3) 구현 모델 

      가. 퍼블릭 클라우드 
		  - CSP(클라우드 서비스를 제공하는 회사)가 운영관리하고 
		    일반 사용자가 서비스를 받는 형태.
			ex. Amazon AWS, Google Cloud, MS Azure 
		  
	  나. 프라이빗 클라우드 
	      - 일반회사에서 자체적으로 클라우드 환경을 구축해서 서비스함.
		  
	  다. 하이브리드 클라우드 
	     - 프라이빗 + 퍼블릭 혼합 형태
		 
  ----------------------------------------------------------------
   4) 클라우드 장점 
     
	 - 자본비용(IT 리소스 구입비용) 대신에 가변비용(클라우드)으로 대체  
	 - 규모의 경제를 통해서 가격이 저렴해짐. 
	 - IT 리소스 용량이 추정 불필요.( 과대/과소 추정된 서버 추정이 불필요 )
	 - 속도 및 대응력 향상 ( 필요한 IT 리소스를 10분안에 구축 가능 )
  ----------------------------------------------------------------
  5) 클라우드 주요 용어 

     가.  고가용성 ( High Availability, HA )
         - 개념:  (장애가 발생되면 장애상황을 해결하여) 서비스를 지속할 수 있는 능력 의미.
		 - 목표:  빠른 복구가 최종 목표임. 
		 - 필요한 기술
		   a. 이중화(다중화, Reduncency )
		      ==> 단일 장애 지점 제거 ( Single Point of Failure: SPOF ) 필수  
		   b. 장애감지 ( health check )
              ==> SpringBoot:  actuator 의존성, /health 엔드포인트 ( ex. /metrics, /beans, /info,..)
			      K8s : Liveness Probe, Readiness Probe
				  LoadBalancer : health check 
		   c. 자동우회(failover)
		     ==> LoadBalancer/K8s(Readiness Probe)의 상태가 unhealty인 경우 요청에서 제외하고
			     healthy로 된 서비스에만 요청하도록 우회시킴.
		     ==> DB를 백업 데이터베이스 사용 
			      Primary DB     Standby DB
		     ==> K8s의 Pod 재생성
		   
		   d. 확장성(Scalability:   )
		   
		      => Autoscaling
			
			e. 무중단배포 ( zero/low downtime development )
			   - Rolling Update: v2 생성하고 v1 삭제, 반복처리해서 최종적으로 v2만 남도록 함.
			   
			   - Blue/Green: 2개의 서버가 필요하고 트래픽을 한번에 변경.
			         Blue: v1 ( 현재 서비스중인 버전 )
					 Green: v2 ( 새로운 버전 )
					 금융권에서 주로사용. 안정적임.  비용이 많이듬.
			    
			   -Canary : 새 버전을 일부 사용자에게만 먼저 배포.
 			   
			
   
	 나. 장애 내구성/내결함성 ( Fault Tolerance )
	    - 개념: 고가용성과 겹치는 부분이 많음.  하지만 한 단계 업그레이드 된 개념.
		       장애가 발생되면 서비스를 지속할 수 있는 능력 의미
		- 목표: 무중단 서비스가 최종 목표임.
		- 필요한 기술
		    a. 고가용성 기술
			b. 격리(isolation) 
			   ==> AWS의 가용역역(AZ)
			   ==> S/W의 격리 기술: circuit breaker ( 장애전파방지)	
								  MSA의 circuit breaker( Resilience4j 의존성 )
								  
		    c. 점진적 기능 감소 ( 전체서비스가 죽는것 대신에 일부기능를 제한)
			d. 자동복구
		    e. 모니터링 ( 프로메테우스(metric 수집)/그라파나(시각화) : 오픈소스,
			             AWS의 CloudWatch ) 
						 
	----------------------------------------------------------------------------
	
	   다. 확장성(Scalability)/ 탄력성( Elasticity )
	   
	      -개념: 트래픽이 증가/감소하면 자원을 늘리고 줄이는 능력
		       ( 수요에 따라서 컴퓨팅 파워를 늘리고 줄이는 능력 )
			   
		  -설계조건 
		    > stateless: 상태를 저장하면 안됨. (***********)
			> fast startup: 빠른 서버 생성 및 감소 
			> Automation: 자동화 필수
			> Monitoring: 실시간 모니터링 필수
		  
	
	  라. 프로비저닝( Provisioning)
	  
	    -개념: 필요한 IT리소스를 준비하고 할당하는 과정을 의미.
		-종류 3가지 
		
		  a. 수동  프로비저닝
		     - 사용자가 직접 생성.
			  (ex. 사용자가 AWS에 로그인해서 버튼클릭하면서 리소스 사용방법 의미)
			 
		  b. 자동  프로비저닝
		    - 사용자가 만든 코드로 생성 (IaC: Infrastructure as Code )
			  ex. AWS의 CloudFormation
			      Terraform
				  Ansible
			
		  c. 동적  프로비저닝
		     - Auto Scaling

4. VPC   ( 10.25.0.0/16)


  1) CIDR 표기법 
  
     문법:  A.B.C.D/E 
	 
  2) CIDR 표기법 해석 
  
    예1>    13.25.82.0/24
	
	가. 10진수를 모두 2진수로 변경하여 표기한다.
	
	       13      25       82       0
	   00001101.00011001.01010010.00000000
	   
	   
	나. CIDR 슬래시 뒤에 있는 숫자를 이용해서 2진수로 자른다.
	
	   00001101.00011001.01010010  /  00000000
	 
	다.  잘린 2진수의 왼쪽값은 그대로 고정하고 , 잘린 2진수의 오른쪽 값에서 표현할 수 있는
	     최소값과 최대값을 구한다.
		 
      최소값:   00001101.00011001.01010010  / 00000000
	  
	  최대값:   00001101.00011001.01010010  / 11111111
	  
	라. 2진수로 표현된 최소값과 최대값을 10진수로 표현한다.
	
	  최소값:   13.25.82.0
	  
	  최대값:   13.25.82.255
	  
	  결론: 13.25.82.0/24 표기법에서 사용가능한 IP 범위:  13.25.82.0 ~ 13.25.82.255
