 1. 서버운영의 역사
 
 
   1) 물리서버시대 ( Bare Metal)
	  - 운영체제에 하나의 서버만 설치(하나의 서비스만 지원)
	  - 서버자원이 남아도 활용불가
	  - 문제점:  서버비용증가
	            확장성이 떨어짐.
				장애발생시 복구어려움.
				
	  
   2) 가상서버시대(Virtual Machine)
      - 하나의 운영체제(host os)에 여러 개의 가상 OS(guest os) 설치됨. 
	  - 서버자원 활용가능 및 서비스 분리가능.
	  - 문제점: 개별적으로 OS 포함 ( OS가 공유안됨 ********)
	           무겁다. 따라서 부팅속도도 느림.
			   디스크/메모리 사용량이 큼.
			   
	  VM = OS + 라이브러리(ex.JDK,JRE)+앱(ex.SpringBoot)  
      여러개의 가상OS를 설치할 수 있으나 서로 공유가 안됨.
	  
	  
    
   3) 컨테이너시대(Docker)
    
	   -핵심: OS가 공유가능. 앱만 분리
	   - 가볍고 빠름.
	   - 동일한 환경으로 실행보장(****************************)
	     (Any OS, Any Language, Any App, Any Where)

3) Docker 기본 흐름

	//////////////////////////////
	
	  registry -------------> image -----------------> container
    
    ex. vsc 홈페이지           VSC 프로그램               VCS 실행(vsc 프로세스)
       intellij홈페이지	     Intellij IDE 프로그램       Intellij 실행(Intellij 프로세스)
	                          클래스(자바클래스)          인스턴스
	
	/////////////////////////////

   가. 개념
   
      Registry ( image 저장소  )
	     |		ex. Docker hub(공식적인 저장소) https://hub.docker.com/ 
		            AWS ECR 

	   image  ( OS + 실행환경 + 라이브러리 + app 관련 정보들이 저장됨.) 
				틀 역할 담당.
		 |	   만드는 방법 2가지: Dockerfile 파일. docker-compose.yml(yaml)
         |
       container ( image를 실제 실행했을 때)		 
		 
	
	나. Registry
	
	  - image 저장소
	    ex. Docker hub(공식적인 저장소), AWS ECR
		
	  - 역할: 이미지 다운로드 ex, docker pull 이미지명:tag (버전)
	         이미지 업로드   ex. docker push 이미지명:tag 
			 버전관리
	  
	다. image
	  - 컨테이너를 만들기 위한 틀 역할 담당.
	  - 구성요소:
	          OS(base 이미지 ex. ubuntu ...)
			  실행환경
			  라이브러리
			  설정파일
			  app
	      ==> 위 구성요소들이 포함될수 있다.
		  
	  -특징:
	        Read-Only(******)
			실행되지 않는 정적파일(static)
			레이어 아키텍쳐(Layer Architecture)로 구성됨. 즉 여러 layer로 구성됨.(*********)
			=> 변경 시, 변경된 layer만 교체되고 나머지는  layer 재사용(캐시)
			
	  -종류
          a. 빌드된 이미지 (pre-build image): docker hub 제공.
          b. 커스텀 이미지 : 개발자가 직접 만든 이미지.
		  
		  
	
	라. container
	 
	  - 정적인 이미지를 실행한 프로세스 의미.
	  - 특징:
	         Read-Write( *******************)
			 하나의 이미지에서 여러개 생성 가능
			 private 구조 (격리된 환경). 따라서 직접 접근이 불가(************)
			 휘발성 ( 컨테이너에서 수정된 변경사항이 일시적임) (***************)
			 => 영속성을 가지기 위해서 볼륨(volume, host에 임의 파일이용 )사용.

 5. hello-world 이미지 실행
  
    1) docker run hello-world 실행
	
	   -내부 동작 순서
	     가.  로컬에서 hello-world 이미지를 찾음.
		     ( 있으면 실행(Container로 만듬)
			  없으면 docker hub에서 다운로드 됨.
		 나.  없기 때문에 docker hub에서 다운로드 됨.
         다. 다운로드 된 이미지 이용해서 컨테이너 생성.		 
		 라. 실행하고 메시지 출력후 종료.
			  
	  - 로컬 이미지 정보 확인
	    
		 docker images
		 
		 IMAGE                ID             DISK USAGE   CONTENT SIZE   EXTRA
         hello-world:latest   0e760fdfbc48       25.9kB         9.49kB    U   
		 
		 hello-world -  이미지명
		 latest   - 태그(tag: 버전이라고 생각하자). 지정하지 않으면 자동으로 latest 가 붙음.
		            latest라고 해서 가장 최신버전의 파일이라고 생각하면 안됨. 
					그냥 tag명으로 지정된 값일뿐이다.
					따라서 명시적으로 버전 지정을 권장함.
					
		ID (0e760fdfbc48_ : 로컬에 있는 이미지 Id값으로서, 식별자용.			
					
		 CONTENT SIZE : 실제 이미지 크기
		 DISK USAGE: 이미지 관리하기위한 디스크 크기.
		 
		 EXTRA : 이미지 사용여부.
		 
	 - 컨테이너 정보 확인
	 
	    docker ps : 실행중인 컨테이너 정보 출력.
		
		
		docker ps -a : 실행중 + 종료된 포함해서 컨테이너 정보 출력.
		
		CONTAINER ID   IMAGE         COMMAND    CREATED          STATUS          PORTS     NAMES
1b19d3e3018f   hello-world   "/hello"   22 minutes ago   Exited (0) 22 minutes ago       kind_chaplygin  

    
	    CONTAINER ID : 실행중인 컨테이너를 식별하기 위한 식별자
		IMAGE:  컨터이너를 만든 템플릿(틀) 이미지.
		command : 명령어
		CREATED:  컨테이너가 생성된 시간.
		STATUS:  컨테이너 상태 (  created, running, stop, exited )
		PORTS: 외부에서 접근할 때 사용하는 포트번호
		NAMES : 컨테이너 이름.
		
		*식별자로 사용: CONTAINER ID, NAMES

6. nginx 웹서버 실행

     1) docker run nginx 실행 ( foreground로 실행 )
	    
		  -내부 동작 순서
	     가.  로컬에서 nginx 이미지를 찾음.
		     ( 있으면 실행(Container로 만듬)
			  없으면 docker hub에서 다운로드 됨.
		 나.  없기 때문에 docker hub에서 다운로드 됨.
		    ==> 명시적으로 tag를 지정하지 않으면 자동으로 latest가 다운로드됨.
         다. 다운로드 된 이미지 이용해서 컨테이너 생성.		 
		 라. 실행하고 메시지 출력후 종료.
		 
	 2) docker run -d nginx:1.30-alpine 실행 ( background로 실행 )
	 
	       -내부 동작 순서
	     가.  로컬에서 nginx:1.30-alpine 이미지를 찾음.
		     ( 있으면 실행(Container로 만듬)
			  없으면 docker hub에서 다운로드 됨.
		 나.  없기 때문에 docker hub에서 다운로드 됨.
		    ==> 명시적으로 tag를 지정했기 때문에 1.30-alpine가 다운로드됨.
         다. 다운로드 된 이미지 이용해서 컨테이너 생성.		 
		 라. 실행하고 메시지 출력후 종료.
		 
		 
	3) docker run -d -p 1234:80 nginx  
	
	  # 포트 포워딩(port forwarding): 
       개념: 컨테이너는 private 환경이기 때문에 외부에서 직접 접근이 불가함.
	        따라서 외부에서 접속할 수 있는 port를 open해야 됨.
			이것이 포트 포워딩(포트매핑) 임.
	   문법:
	        -p host에서요청포트:docker내부포트  ex. -p 1234:80,  -p3306:3306

	1) 이미지 보기
	
	   -개념: 로컬에 저장된 Docker 이미지 목록 조회.
	   -문법: 
	        	docker image ls [OPTIONS] [REPOSITORY[:TAG]]
				
				별칭:  docker image list
				      docker images (*)
		
	   -옵션:
	          -a: 모든 이미지 포함해서 조회.
			     ( untagged 이미지와 dangling 이미지는 기본적으로 조회안됨 )
				   untagged 이미지: 하나의 이미지를 docker tag 명령어로 리눅스의 하드링크처럼
				                  여러 버전을 만들수 있음.
								  이 경우에 특정 버전을 삭제하면 진짜 이미지가 삭제되는 것이 아니고
								  untagged 상태로 남게된다.
								  
				  dangling 이미지: 동일한 이미지(이미지:TAG)를 다시 빌드할 때,
				                기존 이미지가 태그를 잃게됨. 
								이런 이미지를 의미함.
								 <none>:<none> 포맷을 가짐.
								)
								  
			  -q, --quiet :  이미지 ID만 출력
			  
			  --no-trunc  : 정보를 절삭하지 말고 전체 표시.
			  
			  --digests :  Docker hub에 있는 이미지 식별자
			  
			  -f, --filter : 조건으로 필터링 가능.
			                https://docs.docker.com/reference/cli/docker/image/ls/#filter 참조할것
							 ex.  --filter "before=image1"
							 
			  --format : 출력 형식 지정.
			             https://docs.docker.com/reference/cli/docker/image/ls/#format 참조할 것. 
			            기본은 table 형식임.
							//////////////////////////////////////////////
							 다음과 같은 속성 사용 가능.
							  Placeholder	      Description
								.ID	               Image ID
								.Repository	       Image repository
								.Tag	           Image tag
								.Digest	           Image digest
								.CreatedSince	   Elapsed time since the image was created
								.CreatedAt	       Time when the image was created
								.Size	           Image disk size
							//////////////////////////////////////////////
						ex. --format "{{.ID}}: {{.Repository}}"

	   -용도: 버전관리 및 프로파일(ex. prod/dev/test ) 관리용.
			 docker hub에 업로드 할때 주로 사용됨.( 업로드할때 이름이 정해져 있음. )
	
		ex. 
			   docker tag   nginx:latest   nginx:v1
			   docker tag   nginx:latest   nginx:v2
			   docker tag   nginx:latest   nginx:dev
			   docker tag   nginx:latest   nginx:test

     5) docker image 삭제
	 
	    -개념:  로컬에 있는 docker image 삭제
	
	    -특징:  컨테이너로 실행중이면 삭제 불가.
		      반드시 실행중인 컨테이너를 중지하고 삭제까지 하고 
			  나중에 image 삭제 가능.
			  
	   
	   -문법: 
	   
	         docker image rm [OPTIONS] IMAGE [IMAGE...] # 이미지 ID, 이미지명:tag 
			 
			 별칭: docker image remove,  docker rmi (*)
			 
			 
		-옵션:
		
		       docker rmi 0e760fdfbc48  # 이미지 ID
			   
			   docker rmi 5aca99593157  # 동일한 이미지 ID가진  TAG가 여러개인 경우는 ID로 삭제 불가.
			     Error response from daemon: conflict: unable to delete 5aca99593157 (must be forced) - image is referenced in multiple repositories
			   
			   
			   docker rmi nginx:1.30-alpine # 이미지명
			   
			   
			   
			   docker rmi nginx:v1 # 동일한 이미지 ID가진  TAG가 여러개인 경우는 이미지명으로 삭제.
			     Untagged: nginx:v1  # 실제 삭제가 된것이 아니고 untagged 로 출력됨. tag만 삭제된것임.
				 
			   docker rmi nginx:v2
			     Untagged: nginx:v2  # 실제 삭제가 된것이 아니고 untagged 로 출력됨. tag만 삭제된것임.
				 
			   docker rmi nginx:latest # 마지막 남은 이미지를 삭제할 때 진짜로 삭제됨. tag와 이미지 모두 삭제된것임.
			     Untagged: nginx:latest
				 Deleted: sha256:5aca99593157f4ae539a5dec1092a0ad8762f8e2eb1789085a13a0f5622369f6

   6) docker image를 파일로 저장
   
   
       -개념: 로컬에 있는 Docker 이미지를  tar archive ( tar 및 압축 )파일로 저장하는 명령어.
	   
	   -문법: 
	   
	         docker image save [OPTIONS] IMAGE [IMAGE...]
			 =>  docker image save -o  경로/파일명.tar  이미지명
			 
			 별칭: docker save
			 
		-옵션:
		       -o, --output	 : 기본 표준출력(콘솔) 대신에 파일에 출력..
			   
		
		  ex. 
		  
		       docker save -o  nginx.tar   nginx
			   docker save -o  ../nginx.tar   nginx
			   
			   docker save nginx > nginx2.tar  
			   
			   docker save myimage:latest | gzip > myimage_latest.tar.gz # 리눅스에 실습하자.
			   
			==> -o 와 > 했을 때 크기 차이?
                 강사님 save를 쓰면 Docker가 직접 바이너리로 저장하는데, 리다이렉션을 쓰면 PowerShell이 
				 바이너리 데이터를 UTF-16으로 변환한다고 합니다. 
				 이때 인코딩 오버헤드때문에 파일 크기가 증가한다고 하네요.
				 리눅스에서만 동일함. ( 확인하자 )

	 7) 파일로 저장된 docker image를 로드하기
   
   
       -개념: 로컬에 있는 Docker 이미지를  tar archive ( tar 및 압축 )파일로 저장하는 명령어.
	   
	   -문법: 
	   
	        docker image load [OPTIONS]  경로/파일명.tar
			 
			 
			 별칭: docker load
			 
		-옵션:
		       -i, --input : 기본 표준입력(키보드) 대신에 파일에서 읽기
			   
			
		   ex.
		        # 기존 이미지 삭제
				 docker rmi nginx
				 
				# nginx.tar 로부터 로드하기

				docker image load -i  nginx.tar
				  Loaded image: nginx:latest
				  
				docker images  # 로드된 이미지 확인

  8) docker hub에서 로컬로 docker image 내려받기
  
       -개념:  Registry(docker hub)에서 Docker 이미지를 로컬로 다운로드하는 명령어.
			  인증이 필요없음. 즉 누구나 다운로드 가능.
	   
	   
	   -문법: 
	   
	        docker image pull [OPTIONS] NAME[:TAG|@DIGEST]
			 
			 
			 별칭: docker pull
			 
		-옵션:
		
		     -a, --all-tags :  저장소에 있는 모든 이미지 다운로드 ( tag가 다른 이미지 포함)
			 
			 -q, --quiet : 이미지 다운로드할 때 상세정보 출력 안함.
			 
	 ex.
	        docker pull ubuntu
			
			docker pull ubuntu:24.04
