 1. 서버운영의 역사
 
 
   1) 물리서버시대 ( Bare Metal)
	  - 운영체제에 하나의 서버만 설치(하나의 서비스만 지원)
	  - 서버자원이 남아도 활용불가
	  - 문제점:  서버비용증가
	            확장성이 떨어짐.
				장애발생시 복구어려움.
				
	  
   2) 가상서버시대(Virtual Machine)
      - 하나의 운영체제(host os)에 여러 개의 가상 OS(guest os) 설치됨. 
	  - 서버자원 활용가능 및 서비스 분리가능.
	  - 문제점: 개별적으로 OS 포함 ( OS가 공유안됨 ********)
	           무겁다. 따라서 부팅속도도 느림.
			   디스크/메모리 사용량이 큼.
			   
	  VM = OS + 라이브러리(ex.JDK,JRE)+앱(ex.SpringBoot)  
      여러개의 가상OS를 설치할 수 있으나 서로 공유가 안됨.
	  
	  
    
   3) 컨테이너시대(Docker)
    
	   -핵심: OS가 공유가능. 앱만 분리
	   - 가볍고 빠름.
	   - 동일한 환경으로 실행보장(****************************)
	     (Any OS, Any Language, Any App, Any Where)

 2. Container 관련 내용

   1) OCI ( Open Container Initiative )
     - 컨테이너 표준을 만드는 협회.
	 
   2) containerd (*)
      - 컨테이너의 실행환경중 하나임.
	  - Docker에서 사용하는 실행환경임.
  
    3) CRI-O
	  - 컨테이너 관리하는 오케스트레이션이 사용하는 실행환경중 하나임.
	  - K8s(Kubernetes)에서 사용하는 실행환경임.

3. Docker
 
   1)개념
      - 컨테이너를 만들고 관리하기 위한 오픈소스 S/W.
	  - 한번 만들면 어떤 환경에서건 동일한 환경구축 가능.
	  
   2) 장점
       - 환경불일치 해결( 어디서 실행해도 동일한 결과 보장 )
	   - 배포 표준화 및 자동화 
	   - 빠른 배포 및 롤백
	   - 마이크로서비스 어플리케이션(MSA) 개발에 최적화
	   
3) Docker 기본 흐름

	//////////////////////////////
	
	  registry -------------> image -----------------> container
    
    ex. vsc 홈페이지           VSC 프로그램               VCS 실행(vsc 프로세스)
       intellij홈페이지	     Intellij IDE 프로그램       Intellij 실행(Intellij 프로세스)
	                          클래스(자바클래스)          인스턴스
	
	/////////////////////////////

   가. 개념
   
      Registry ( image 저장소  )
	     |		ex. Docker hub(공식적인 저장소) https://hub.docker.com/ 
		            AWS ECR 

	   image  ( OS + 실행환경 + 라이브러리 + app 관련 정보들이 저장됨.) 
				틀 역할 담당.
		 |	   만드는 방법 2가지: Dockerfile 파일. docker-compose.yml(yaml)
         |
       container ( image를 실제 실행했을 때)		 
		 
	
	나. Registry
	
	  - image 저장소
	    ex. Docker hub(공식적인 저장소), AWS ECR
		
	  - 역할: 이미지 다운로드 ex, docker pull 이미지명:tag (버전)
	         이미지 업로드   ex. docker push 이미지명:tag 
			 버전관리
	  
	다. image
	  - 컨테이너를 만들기 위한 틀 역할 담당.
	  - 구성요소:
	          OS(base 이미지 ex. ubuntu ...)
			  실행환경
			  라이브러리
			  설정파일
			  app
	      ==> 위 구성요소들이 포함될수 있다.
		  
	  -특징:
	        Read-Only(******)
			실행되지 않는 정적파일(static)
			레이어 아키텍쳐(Layer Architecture)로 구성됨. 즉 여러 layer로 구성됨.(*********)
			=> 변경 시, 변경된 layer만 교체되고 나머지는  layer 재사용(캐시)
			
	  -종류
          a. 빌드된 이미지 (pre-build image): docker hub 제공.
          b. 커스텀 이미지 : 개발자가 직접 만든 이미지.
		  
		  
	
	라. container
	 
	  - 정적인 이미지를 실행한 프로세스 의미.
	  - 특징:
	         Read-Write( *******************)
			 하나의 이미지에서 여러개 생성 가능
			 private 구조 (격리된 환경). 따라서 직접 접근이 불가(************)
			 휘발성 ( 컨테이너에서 수정된 변경사항이 일시적임) (***************)
			 => 영속성을 가지기 위해서 볼륨(volume, host에 임의 파일이용 )사용.
