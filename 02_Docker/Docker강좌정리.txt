 1. 서버운영의 역사
 
 
   1) 물리서버시대 ( Bare Metal)
	  - 운영체제에 하나의 서버만 설치(하나의 서비스만 지원)
	  - 서버자원이 남아도 활용불가
	  - 문제점:  서버비용증가
	            확장성이 떨어짐.
				장애발생시 복구어려움.
				
	  
   2) 가상서버시대(Virtual Machine)
      - 하나의 운영체제(host os)에 여러 개의 가상 OS(guest os) 설치됨. 
	  - 서버자원 활용가능 및 서비스 분리가능.
	  - 문제점: 개별적으로 OS 포함 ( OS가 공유안됨 ********)
	           무겁다. 따라서 부팅속도도 느림.
			   디스크/메모리 사용량이 큼.
			   
	  VM = OS + 라이브러리(ex.JDK,JRE)+앱(ex.SpringBoot)  
      여러개의 가상OS를 설치할 수 있으나 서로 공유가 안됨.
	  
	  
    
   3) 컨테이너시대(Docker)
    
	   -핵심: OS가 공유가능. 앱만 분리
	   - 가볍고 빠름.
	   - 동일한 환경으로 실행보장(****************************)
	     (Any OS, Any Language, Any App, Any Where)

3) Docker 기본 흐름

	//////////////////////////////
	
	  registry -------------> image -----------------> container
    
    ex. vsc 홈페이지           VSC 프로그램               VCS 실행(vsc 프로세스)
       intellij홈페이지	     Intellij IDE 프로그램       Intellij 실행(Intellij 프로세스)
	                          클래스(자바클래스)          인스턴스
	
	/////////////////////////////

   가. 개념
   
      Registry ( image 저장소  )
	     |		ex. Docker hub(공식적인 저장소) https://hub.docker.com/ 
		            AWS ECR 

	   image  ( OS + 실행환경 + 라이브러리 + app 관련 정보들이 저장됨.) 
				틀 역할 담당.
		 |	   만드는 방법 2가지: Dockerfile 파일. docker-compose.yml(yaml)
         |
       container ( image를 실제 실행했을 때)		 
		 
	
	나. Registry
	
	  - image 저장소
	    ex. Docker hub(공식적인 저장소), AWS ECR
		
	  - 역할: 이미지 다운로드 ex, docker pull 이미지명:tag (버전)
	         이미지 업로드   ex. docker push 이미지명:tag 
			 버전관리
	  
	다. image
	  - 컨테이너를 만들기 위한 틀 역할 담당.
	  - 구성요소:
	          OS(base 이미지 ex. ubuntu ...)
			  실행환경
			  라이브러리
			  설정파일
			  app
	      ==> 위 구성요소들이 포함될수 있다.
		  
	  -특징:
	        Read-Only(******)
			실행되지 않는 정적파일(static)
			레이어 아키텍쳐(Layer Architecture)로 구성됨. 즉 여러 layer로 구성됨.(*********)
			=> 변경 시, 변경된 layer만 교체되고 나머지는  layer 재사용(캐시)
			
	  -종류
          a. 빌드된 이미지 (pre-build image): docker hub 제공.
          b. 커스텀 이미지 : 개발자가 직접 만든 이미지.
		  
		  
	
	라. container
	 
	  - 정적인 이미지를 실행한 프로세스 의미.
	  - 특징:
	         Read-Write( *******************)
			 하나의 이미지에서 여러개 생성 가능
			 private 구조 (격리된 환경). 따라서 직접 접근이 불가(************)
			 휘발성 ( 컨테이너에서 수정된 변경사항이 일시적임) (***************)
			 => 영속성을 가지기 위해서 볼륨(volume, host에 임의 파일이용 )사용.

 5. hello-world 이미지 실행
  
    1) docker run hello-world 실행
	
	   -내부 동작 순서
	     가.  로컬에서 hello-world 이미지를 찾음.
		     ( 있으면 실행(Container로 만듬)
			  없으면 docker hub에서 다운로드 됨.
		 나.  없기 때문에 docker hub에서 다운로드 됨.
         다. 다운로드 된 이미지 이용해서 컨테이너 생성.		 
		 라. 실행하고 메시지 출력후 종료.
			  
	  - 로컬 이미지 정보 확인
	    
		 docker images
		 
		 IMAGE                ID             DISK USAGE   CONTENT SIZE   EXTRA
         hello-world:latest   0e760fdfbc48       25.9kB         9.49kB    U   
		 
		 hello-world -  이미지명
		 latest   - 태그(tag: 버전이라고 생각하자). 지정하지 않으면 자동으로 latest 가 붙음.
		            latest라고 해서 가장 최신버전의 파일이라고 생각하면 안됨. 
					그냥 tag명으로 지정된 값일뿐이다.
					따라서 명시적으로 버전 지정을 권장함.
					
		ID (0e760fdfbc48_ : 로컬에 있는 이미지 Id값으로서, 식별자용.			
					
		 CONTENT SIZE : 실제 이미지 크기
		 DISK USAGE: 이미지 관리하기위한 디스크 크기.
		 
		 EXTRA : 이미지 사용여부.
		 
	 - 컨테이너 정보 확인
	 
	    docker ps : 실행중인 컨테이너 정보 출력.
		
		
		docker ps -a : 실행중 + 종료된 포함해서 컨테이너 정보 출력.
		
		CONTAINER ID   IMAGE         COMMAND    CREATED          STATUS          PORTS     NAMES
1b19d3e3018f   hello-world   "/hello"   22 minutes ago   Exited (0) 22 minutes ago       kind_chaplygin  

    
	    CONTAINER ID : 실행중인 컨테이너를 식별하기 위한 식별자
		IMAGE:  컨터이너를 만든 템플릿(틀) 이미지.
		command : 명령어
		CREATED:  컨테이너가 생성된 시간.
		STATUS:  컨테이너 상태 (  created, running, stop, exited )
		PORTS: 외부에서 접근할 때 사용하는 포트번호
		NAMES : 컨테이너 이름.
		
		*식별자로 사용: CONTAINER ID, NAMES
