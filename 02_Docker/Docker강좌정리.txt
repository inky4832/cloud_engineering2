 1. 서버운영의 역사
 
 
   1) 물리서버시대 ( Bare Metal)
	  - 운영체제에 하나의 서버만 설치(하나의 서비스만 지원)
	  - 서버자원이 남아도 활용불가
	  - 문제점:  서버비용증가
	            확장성이 떨어짐.
				장애발생시 복구어려움.
				
	  
   2) 가상서버시대(Virtual Machine)
      - 하나의 운영체제(host os)에 여러 개의 가상 OS(guest os) 설치됨. 
	  - 서버자원 활용가능 및 서비스 분리가능.
	  - 문제점: 개별적으로 OS 포함 ( OS가 공유안됨 ********)
	           무겁다. 따라서 부팅속도도 느림.
			   디스크/메모리 사용량이 큼.
			   
	  VM = OS + 라이브러리(ex.JDK,JRE)+앱(ex.SpringBoot)  
      여러개의 가상OS를 설치할 수 있으나 서로 공유가 안됨.
	  
	  
    
   3) 컨테이너시대(Docker)
    
	   -핵심: OS가 공유가능. 앱만 분리
	   - 가볍고 빠름.
	   - 동일한 환경으로 실행보장(****************************)
	     (Any OS, Any Language, Any App, Any Where)

3) Docker 기본 흐름

	//////////////////////////////
	
	  registry -------------> image -----------------> container
    
    ex. vsc 홈페이지           VSC 프로그램               VCS 실행(vsc 프로세스)
       intellij홈페이지	     Intellij IDE 프로그램       Intellij 실행(Intellij 프로세스)
	                          클래스(자바클래스)          인스턴스
	
	/////////////////////////////

   가. 개념
   
      Registry ( image 저장소  )
	     |		ex. Docker hub(공식적인 저장소) https://hub.docker.com/ 
		            AWS ECR 

	   image  ( OS + 실행환경 + 라이브러리 + app 관련 정보들이 저장됨.) 
				틀 역할 담당.
		 |	   만드는 방법 2가지: Dockerfile 파일. docker-compose.yml(yaml)
         |
       container ( image를 실제 실행했을 때)		 
		 
	
	나. Registry
	
	  - image 저장소
	    ex. Docker hub(공식적인 저장소), AWS ECR
		
	  - 역할: 이미지 다운로드 ex, docker pull 이미지명:tag (버전)
	         이미지 업로드   ex. docker push 이미지명:tag 
			 버전관리
	  
	다. image
	  - 컨테이너를 만들기 위한 틀 역할 담당.
	  - 구성요소:
	          OS(base 이미지 ex. ubuntu ...)
			  실행환경
			  라이브러리
			  설정파일
			  app
	      ==> 위 구성요소들이 포함될수 있다.
		  
	  -특징:
	        Read-Only(******)
			실행되지 않는 정적파일(static)
			레이어 아키텍쳐(Layer Architecture)로 구성됨. 즉 여러 layer로 구성됨.(*********)
			=> 변경 시, 변경된 layer만 교체되고 나머지는  layer 재사용(캐시)
			
	  -종류
          a. 빌드된 이미지 (pre-build image): docker hub 제공.
          b. 커스텀 이미지 : 개발자가 직접 만든 이미지.
		  
		  
	
	라. container
	 
	  - 정적인 이미지를 실행한 프로세스 의미.
	  - 특징:
	         Read-Write( *******************)
			 하나의 이미지에서 여러개 생성 가능
			 private 구조 (격리된 환경). 따라서 직접 접근이 불가(************)
			 휘발성 ( 컨테이너에서 수정된 변경사항이 일시적임) (***************)
			 => 영속성을 가지기 위해서 볼륨(volume, host에 임의 파일이용 )사용.

 5. hello-world 이미지 실행
  
    1) docker run hello-world 실행
	
	   -내부 동작 순서
	     가.  로컬에서 hello-world 이미지를 찾음.
		     ( 있으면 실행(Container로 만듬)
			  없으면 docker hub에서 다운로드 됨.
		 나.  없기 때문에 docker hub에서 다운로드 됨.
         다. 다운로드 된 이미지 이용해서 컨테이너 생성.		 
		 라. 실행하고 메시지 출력후 종료.
			  
	  - 로컬 이미지 정보 확인
	    
		 docker images
		 
		 IMAGE                ID             DISK USAGE   CONTENT SIZE   EXTRA
         hello-world:latest   0e760fdfbc48       25.9kB         9.49kB    U   
		 
		 hello-world -  이미지명
		 latest   - 태그(tag: 버전이라고 생각하자). 지정하지 않으면 자동으로 latest 가 붙음.
		            latest라고 해서 가장 최신버전의 파일이라고 생각하면 안됨. 
					그냥 tag명으로 지정된 값일뿐이다.
					따라서 명시적으로 버전 지정을 권장함.
					
		ID (0e760fdfbc48_ : 로컬에 있는 이미지 Id값으로서, 식별자용.			
					
		 CONTENT SIZE : 실제 이미지 크기
		 DISK USAGE: 이미지 관리하기위한 디스크 크기.
		 
		 EXTRA : 이미지 사용여부.
		 
	 - 컨테이너 정보 확인
	 
	    docker ps : 실행중인 컨테이너 정보 출력.
		
		
		docker ps -a : 실행중 + 종료된 포함해서 컨테이너 정보 출력.
		
		CONTAINER ID   IMAGE         COMMAND    CREATED          STATUS          PORTS     NAMES
1b19d3e3018f   hello-world   "/hello"   22 minutes ago   Exited (0) 22 minutes ago       kind_chaplygin  

    
	    CONTAINER ID : 실행중인 컨테이너를 식별하기 위한 식별자
		IMAGE:  컨터이너를 만든 템플릿(틀) 이미지.
		command : 명령어
		CREATED:  컨테이너가 생성된 시간.
		STATUS:  컨테이너 상태 (  created, running, stop, exited )
		PORTS: 외부에서 접근할 때 사용하는 포트번호
		NAMES : 컨테이너 이름.
		
		*식별자로 사용: CONTAINER ID, NAMES

6. nginx 웹서버 실행

     1) docker run nginx 실행 ( foreground로 실행 )
	    
		  -내부 동작 순서
	     가.  로컬에서 nginx 이미지를 찾음.
		     ( 있으면 실행(Container로 만듬)
			  없으면 docker hub에서 다운로드 됨.
		 나.  없기 때문에 docker hub에서 다운로드 됨.
		    ==> 명시적으로 tag를 지정하지 않으면 자동으로 latest가 다운로드됨.
         다. 다운로드 된 이미지 이용해서 컨테이너 생성.		 
		 라. 실행하고 메시지 출력후 종료.
		 
	 2) docker run -d nginx:1.30-alpine 실행 ( background로 실행 )
	 
	       -내부 동작 순서
	     가.  로컬에서 nginx:1.30-alpine 이미지를 찾음.
		     ( 있으면 실행(Container로 만듬)
			  없으면 docker hub에서 다운로드 됨.
		 나.  없기 때문에 docker hub에서 다운로드 됨.
		    ==> 명시적으로 tag를 지정했기 때문에 1.30-alpine가 다운로드됨.
         다. 다운로드 된 이미지 이용해서 컨테이너 생성.		 
		 라. 실행하고 메시지 출력후 종료.
		 
		 
	3) docker run -d -p 1234:80 nginx  
	
	  # 포트 포워딩(port forwarding): 
       개념: 컨테이너는 private 환경이기 때문에 외부에서 직접 접근이 불가함.
	        따라서 외부에서 접속할 수 있는 port를 open해야 됨.
			이것이 포트 포워딩(포트매핑) 임.
	   문법:
	        -p host에서요청포트:docker내부포트  ex. -p 1234:80,  -p3306:3306

	1) 이미지 보기
	
	   -개념: 로컬에 저장된 Docker 이미지 목록 조회.
	   -문법: 
	        	docker image ls [OPTIONS] [REPOSITORY[:TAG]]
				
				별칭:  docker image list
				      docker images (*)
		
	   -옵션:
	          -a: 모든 이미지 포함해서 조회.
			     ( untagged 이미지와 dangling 이미지는 기본적으로 조회안됨 )
				   untagged 이미지: 하나의 이미지를 docker tag 명령어로 리눅스의 하드링크처럼
				                  여러 버전을 만들수 있음.
								  이 경우에 특정 버전을 삭제하면 진짜 이미지가 삭제되는 것이 아니고
								  untagged 상태로 남게된다.
								  
				  dangling 이미지: 동일한 이미지(이미지:TAG)를 다시 빌드할 때,
				                기존 이미지가 태그를 잃게됨. 
								이런 이미지를 의미함.
								 <none>:<none> 포맷을 가짐.
								)
								  
			  -q, --quiet :  이미지 ID만 출력
			  
			  --no-trunc  : 정보를 절삭하지 말고 전체 표시.
			  
			  --digests :  Docker hub에 있는 이미지 식별자
			  
			  -f, --filter : 조건으로 필터링 가능.
			                https://docs.docker.com/reference/cli/docker/image/ls/#filter 참조할것
							 ex.  --filter "before=image1"
							 
			  --format : 출력 형식 지정.
			             https://docs.docker.com/reference/cli/docker/image/ls/#format 참조할 것. 
			            기본은 table 형식임.
							//////////////////////////////////////////////
							 다음과 같은 속성 사용 가능.
							  Placeholder	      Description
								.ID	               Image ID
								.Repository	       Image repository
								.Tag	           Image tag
								.Digest	           Image digest
								.CreatedSince	   Elapsed time since the image was created
								.CreatedAt	       Time when the image was created
								.Size	           Image disk size
							//////////////////////////////////////////////
						ex. --format "{{.ID}}: {{.Repository}}"
		실습:
		      docker image ls

	1) 컨테이너 생성
	
	   -개념: 로컬에 있는 Docker 이미지를 사용하여 컨테이너를 생성.
	          실행은 안됨.
	   
	   -문법: 
	        	docker container create [OPTIONS] IMAGE [COMMAND] [ARG...]
				
				별칭:  docker create
		
	   -옵션:		
	         --name:  컨테이너 이름.  (지정하지 않으면 랜덤하게 설정됨 )
			 -p, --publish:  포트매핑 
			 -e, --env : 환경변수 설정 
			 --env-file : 환경변수 설정된 파일일기
			 -v, --volume: 볼륨연결 ( host의 임의 파일과 연결 )
			 
			 --network : 동일한 네트워크로 묶기 위해서 사용함.
			 
			 -i, --interactive : 표준입력(키보드) 활성화
			 -t, --tty         : 모니터
			 ==> -it  : 컨테이너에 접속시 사용하는 옵션
		ex. 
		
		        docker create --name my-nginx  nginx 
				
				docker create --name my-nginx2 -p 1234:80  nginx 
				
			    docker create --name some-mysql -e MYSQL_ROOT_PASSWORD=1234 mysql:8.3

				-v /my/own/datadir:/var/lib/mysql  mysql:8.3
				
				# 서로 다른 컨테이너들을 동일 네트워크로 묶는 방법. 묶으면 컨테이너명으로 접근이 가능해짐(**********)

				# -it 옵션은 실제 컨테이너에 접속할 때 사용하는 옵션.
				docker create -it --name my-nginx  nginx sh      #  ubuntu는 bash 사용하고 nginx는 sh 사용.
				docker create --name my-ubuntu  -it  ubuntu bash  # 나중에 start하면 bash로 접속가능     
				
				docker ps -a   # STATUS값이 Created 임.  실행은 안됨.

	3) 컨테이너 종료(stop)
	
	   -개념:  실행(Running)중인 컨테이너를 정상적으로 종료( Graceful Shutdown)하는 명령어.
	   
	   -문법: 
	        	docker container stop [OPTIONS] CONTAINER [CONTAINER...]
				
				별칭:  docker stop
		
	   -옵션:		
	   
	          -s, --signal : 컨테이너에 보내는 신호. 실제종료하기 전 준비작업 위한 용도.		
			  -t, --timeout : 컨테이너 실제 종료되기 전 wait 시간 ( 단위: seconds )
							  Linux: 10초, Window: 30초
							  
		- 종료 내부 동작

				1단계: 종료신호(SIGTERM)전달 <== DB연동,파일연동 중 작업이 손상되지 않도록 하기 위함.
				2단계: 어플리케이션이 정리 작업 수행
				3단계: 일정시간 대기(  Linux:10초, Window:30초)
				4단계: 종료안되면 SIGKILL 전달
				5단계: 종료.
		
		  ex.
		       docker ps
			   
			   docker stop f916eea5608e # 컨테이너 ID
			   
			   docker stop  some-mysql  my-nginx2  # 여러개 지정 가능
			   
			   docker stop -t 20  my-nginx  # 20초뒤 종료됨.
			   
			   # 모두 컨테이너 종료
			   docker ps -q 이용
			   docker stop $(docker ps -q)
			   
			   
			   docker start f916eea5608e  # 중지된 컨테이너 다시 시작.
			   
		////////////////////////////////
		  start vs restart
		  
		  -docker start: Created 또는 Stopped된 컨테이너를 다시 시작할 때 사용.
		  -docker restart: 실행(Running)중인 컨테이너를 다시 시작 ( stop-->start )

	        	docker container ls [OPTIONS]
				
				
				별칭:  docker container list, docker container ps, docker ps			
				
	  -옵션: 		
	  
	        -a, --all: 모든 컨테이너 조회 ( 실행중 + 종료됨(stoppend) + 생성됨(created) )

			-l, --latest : 가장 최근에 생성된 컨테이너 1개만 조회.
	        -n, --last   : 최근에 생성된 n개의 컨테이너 조회. (  실행중 + 종료됨(stoppend) + 생성됨(created) 포함 )
			--no-trunc : 전체 값 상세하게 출력.
			-f, --filter	: 조건검색으로 필터링함.
							 ex. docker ps --filter status=running # created|running|paused|restarting|exited|dead
							     docker ps --filter ancestor=ubuntu  # image, image:tag, image:tag@digest, id
								 docker ps --filter before=ubuntu  
								 docker ps -f since=6e63f6ff38b0
								 docker ps --filter volume=/data
								 docker ps --filter network=net1
								 docker ps --filter publish=80
								 docker ps --filter "name=nostalgic"  # 컨테이너이름 검색

			--format : 원하는 형식으로 출력.
			             //////////////////////////////////////////////
							 다음과 같은 속성 사용 가능.
							  Placeholder	      Description
								.ID	               Container  ID
								.Image             Image ID
								.CreatedAt	       Time when the image was created
								.RunningFor 	   경과시간
								.Ports 			    expose한 포트번호
								.State              Container status (for example; "created", "running", "exited").
								.Status			    서비스 상태 ( 서비스 가능여부 )
								.Size	           Container  disk size
								.Names				Container names.
								.Networks          Names of the networks attached to this container.
								
								ex. docker ps --format "{{.ID}}: {{.Command}}"
							//////////////////////////////////////////////
	 ex. 						 
	       docker ps
		   docker ps -a
		   
		   
		   docker ps -q 
		   # docker stop $(docker ps -q)  <== 실행중인 모든 컨테이너 종료
		   
		   docker ps -l     #  가장 최근에 생성된 컨테이너

 2.  Docker에서 데이터를 영속성으로 관리하는 방법 2가지.
 
     - 2개 모두 데이터를 영구적으로 보존이 가능함.
	 - 차이점은 관리주체와 사용목적이 다름.
 
    1) 볼륨(Volume) 이용.
	    -관리주체: Docker 가 관리.
		-생성방법:
		         docker volume create 볼륨명
				 ex. docker volume create my-volume
				 
	    -실제사용경로: 
						-v my-volume:/usr/lib
		-이식성(다른곳에서 사용):  Docker 가 관리하기 때문에 이식성이 우수;
		- 성능: Docker 가 관리하기 때문에 안정적.
		- 목적: DB 데이터 (*****) ex. mysql
		
	2) 바인드마운트(Bind Mount)이용.
	    -관리주체: 사용자(개발자) 가 관리.
		          직접 host에 폴더 생성하고 경로 관리해야됨.(****)
				  
		-생성방법:
		         host에 실제 물리적인 디렉터리 생성
				 윈도우: C:\cloud_engineering\Docker\tempDir
				 Linux:  /home/user1/temp
				 
	    -실제사용경로: 
						-v C:\cloud_engineering\Docker\tempDir:/usr/lib		 
					    -v /home/user1/temp:/usr/lib		 	

		-이식성(다른곳에서 사용): 개발자가 관리하기 때문에 이식성이 떨어짐.
                              이유는 서버마다 경로가 다름.		
		
		- 성능:  host파일을 직접 접근하기 때문에 I/O 발생됨.
		        따라서 성능이 떨어짐.
				
		- 목적: 개발코드 (******) 
		       코드 수정하면 바로 적용됨.

4장. Docker 환경변수
//////////////////////////

   1. 개념
      - 컨테이너 실행 시 외부에서 값을 주입해서 컨테이너안의 어플리케이션에서 사용하는 방법.
	    ( SpringBoot에서의 external configuration 개념과 동일 )
		
   2. 컨테이너내에서 환경변수 확인 방법

     # 현재 쉘 환경변수 보기
      env    
	  printenv
	  
	 # 특정 변수 보기
	 echo $key값
	   
	   ex. echo $SHELL
	       echo $HOME
	  
   3. 외부에서 환경변수 주입 방법

     가. -e, --env 옵션 이용
		
		 - 값하나씩 설정.
		 - 실행 시 동적으로 환경변수 주입 가능.
		 - 우선순위가 가장 높다.
		
		 ex.  
		     docker run -e key=value  -e key1=value1  이미지명
	
     나. --env-file 이용
	     
		- 파일에 저장한 후 한번에 적용. 
		- 실행 시 동적으로 환경변수 주입 가능.
		- 일반적으로 .env 파일로 만듬.
		
		 ex.  
		     docker run --env-file=.env  이미지명

    다. 우선순위
	
	    1순위: -e

		K8s   기반: Deployment, Service, Pod, ....  모두 yaml파일로 구축함.
		AWS 기반:  terraform 이용해서 EC2, RDS, VPC 인프라 구축함.
		
	  -특징:
         동일한 환경을 언제든지 재현 가능.
		 Git 으로 버전관리 가능.
		 자동화/표준화 쉽게 적용 가능.
		 
	2. Dockerfile 파일 
	
	 https://docs.docker.com/reference/dockerfile/
	 
	    1) 개념
		 - Docker image를 생성하기 위한 템플릿	
		 
		2) 동작 프로세스
		
		    Dockerfile 
			   |
			 docker build 명령어 실행

		     docker 이미지 생성 ( 커스텀 이미지, base 이미지 필요함(***) )
			    |

			    |
			 컨테이너 실행
			 
	3. 기본 구조 

        FROM  base 이미지	ex. node:14-alpine, eclipse-temurin:21-jre

		WORKDIR 작업디렉터리지정(여러작업들의 기준이 되는 경로) ex. /app

		RUN 실행되는 명령어   ex. npm install ( 결과는 의존성이 설치. node_modules 폴더에 의존성이 저장됨.)

		COPY 호스트파일을 컨테이너에 복사  ex. . .

               실제 포트는 -p 1234:80 지정해야됨.
			   
		CMD 실행되는 명령어  ex. ["node", "app.js"]	 node app.js 동일
				
		ENTRYPOINT 	실행되는 명령어

   4. 주요 명령어 정리
   
      1) FROM 명령어
	  
	     -문법
		      FROM [--platform=<platform>] <image>              [AS <name>]
			  FROM [--platform=<platform>] <image>[:<tag>]      [AS <name>]
			  FROM [--platform=<platform>] <image>[@<digest>]   [AS <name>]
	  
	    - 용도: base image 지정.
		- 특징: 필수.
		       여러번 사용 가능.
			   
			   AS <name> : 별칭. 나중에 멀티-스테이징-빌드 패턴시 참조해서 사용함.
			    https://docs.docker.com/build/building/best-practices/
                https://docs.docker.com/build/building/multi-stage/

     2) WORKDIR
	 
	    -문법
		     WORKDIR /path/to/workdir
			 
		-용도: 내부 작업디렉터리 지정 ( 지정된 디렉터리가 없으면 자동생성 )
		      이후에 사용하는 RUN, CMD, ENTRYPOINT 등의  기준으로 사용됨.
			  
	 
	 3) COPY 
	 
	   -문법
	   
	       COPY [OPTIONS] <src> ... <dest>
		   COPY [OPTIONS] ["<src>", ... "<dest>"]
		   
		   COPY [--from=<image|stage|context>] <src> ... <dest> # 멀티 스테이지 패턴에서 사용됨.
		   
		-용도: 호스트의 파일을 컨테이이너 이미지에 복사
	     
	 4) RUN
	 
	    -문법
		        # Shell form:
				RUN [OPTIONS] <command> ...
				# Exec form:
				RUN [OPTIONS] [ "<command>", ... ]
				
		-용도: 이미지가 만들어지는 동안 ( docker build ) 실행됨.(*******************)	
			  한번만 실행되고 실행된 결과가 이미지 Layer에 저장됨.
			  나중에 변경 불가 ( 변경할려면 이미지를 다시 만들어야 됨)
			  
			  ex. RUN apt update && apt fulll-upgrade -y
				  RUN npm install
	 5) CMD

		-문법
		    CMD ["executable","param1","param2"] (exec form)
			CMD ["param1","param2"] (exec form, as default parameters to ENTRYPOINT)
			CMD command param1 param2 (shell form)
				
			 ex. CMD ["node", "app.js"]
			     CMD ["java", "-jar" ,"app.jar"]
				
		-용도: 컨테이너가 실행될 때 실행됨 (*****************)		
		      docker run 할 때 CMD 명령어를 덮어쓰기 가능함.
			  
			  ex. docker run -d --name my-app -p 8080:80  app2.js  <== app.js가 app2.js 로 동적으로 변경가능.

	  6) ENTRYPOINT ( 고정 명령어 )

       - 문법:
              ENTRYPOINT ["executable", "param1", "param2"]  (exec form)
              ENTRYPOINT command param1 param2			     (shell form)
			  
		-용도: 	컨테이너가 실행될 때 실행됨  
		        docker run 할 때  명령어를 덮어쓰기 힘듬.  
			  
			     ENTRYPOINT ["node", "app.js"]
			     ENTRYPOINT ["java", "-jar" ,"app.jar"]
				 
				  ENTRYPOINT ["java", "-jar"]
				  CMD ["app.jar"]
	
      7) EXPOSE
  
         -문법:
   		      EXPOSE <port>
			  
		- 용도:  컨테이너가 사용하는 포트가 뭔지를 알려주는 용도로 사용됨. (문서화)
                실제 port를 사용할수 있게 open(publish)하지 않음.
				실제 사용하기 위해서는 명시적으로 -p 1234:80 해야 됨.	
				
				
	  8) ENV
	  
      - 문법
                ENV <key>=<value> [<key>=<value>...]

        -용도:  환경변수 설정. 				
			    docker run 할 때  ENV값  덮어쓰기 가능함.
				
		
	  9) VOLUME
 
       -문법:
             VOLUME ["/data"]	   
		
		-용도:  컨네이너의 변경사항을 유지하는 목적임.
		
				FROM ubuntu
				RUN mkdir /myvol
				RUN echo "hello world" > /myvol/greeting
				VOLUME /myvol

    5. Dockerfile 빌드 명령어.
	
	    1) 개념.
		  - Dockerfile 파일을 이용해서 이미지를 생성(빌드)하는 명령어.
		  
		2)문법:
  		        docker buildx build [OPTIONS] PATH | URL | -
				
				별칭: docker build, docker builder build,  docker image build

        3) 옵션:
		         -t, --tag : 이미지이름과 tag 지정.
				 -f, --file :   기본적인 Dockerfile 파일명이나 위치가 다를때 직접 지정.
								ex.   docker build -t my-front-app:v1  .  # 기본적으로 현재 디렉터리의 Dockerfile 찾음
								      docker build -t my-front-app:v1 -f My_Dockerfile .  # 명시된  My_Dockerfile 사용함.
										docker build -t my-front-app:v1 -f ../../Dockerfile  .  # 명시된 경로에서 Dockerfile 찾음
										
				--no-cache : 캐시를 사용하지 않고 새로 빌드함.

6장. Docker Compose
/////////////////////////
  
  https://docs.docker.com/reference/compose-file/services/ 참조
  
  1. 개념
    여러개의 컨테이너(서비스)를 한번에 정의하고, 한번에 실행/중지/삭제가 가능하도록 지원하는 도구.
	
 2. 파일명
    
      docker-compose.yaml (yml)
      compose.yaml(yml)
	  
  3. 특징
     - 필요할 때 Dockerfile 사용가능.  
	 - 자동으로 동일한 네트워크로 묶임 (*****)
	    ==> 서비스간에 IP가 아닌 서비스명으로 접근이 가능하다.
		==> 일반적으로는 명시적으로 네트워크를 지정함.( 분리하기 위함 )
		   
		    ex.
				   front-end     back-end        mysql
				   (vue.js)      (springboot)
			       

	 - 여러 컨테이너를 한번에 시작 및 종료 가능.
	 -  depends_on: 속성으로 컨테이너 실행 순서를 지정가능.
	 
  4. docker compose 기본 구조.
  
   
        services:   # 최상위 속성 
		  web:      # 서비스명 ( 임의의 값 ) <=== 하나의 컨테이너가 됨. 
			image: nginx:latest  # base image 명
			ports:               # post forwarding , -p 8080:80  동일.
			  - "8080:80"

		  db:       # 서비스명 ( 임의의 값 ) <== 하나의 컨테이너가 됨. 
			image: postgres:18  # base image 명
			environment:        # 환경변수,  Dockerfile에서의 ENV 와 동일.
			  POSTGRES_USER: example  # key값은 대문자로 지정(관례)
			  POSTGRES_DB: exampledb
			volumes:            # 영속성 위함 볼륨.  -v 볼륨명:/var/lib/mysql
			  - type: bind
				source: ./proxy/nginx.conf
				target: /etc/nginx/conf.d/default.conf
				read_only: true
	
  5. 문법 정리

     1) services 속성
	 
	     - 최상위 속성
		 - 하위에 여러 서비스를 가질 수 있음.
		   각 서비스는 하나의 컨테이너라고 할 수 있음.
		   
		 - 구성 
               		 
				services:
				  서비스:  # 하나의 컨테이너
				    image: # 사용할 Docker 이미지 ( base image ),없으면 다운로드
					         hub에서 제공하는 offical image 또는 Dockerfile 로 만든 커스텀이미지.
					build: # Dockerfile에서 직접 이미지 생성.	
					container_name: # 컨테이너이름.   --name spring-mysql-demo4 동일
					command: # 명령어, Dockerfile 의 CMD와 동일. 덮어쓰기 가능.		 
							  command: /bin/sh -c 'echo "hello $$HOSTNAME"'
							  ( 컨테이너 실행시 shell 명령어를 사용할려면 /bin/sh -c '명령어' 
							  
					entrypoint: # 명령어. Dockerfile 의 entrypoint와 동일, 덮어쓰기 불가.
					ports:  # 포트포워딩(포트맵핑),  -p 8080:80 동일.
					expose: # 포트 문서화 , Dockerfile의 EXPOSE 와 동일.
					
					networks: 명시적으로 네트워트 지정  #  docker network create 동일.
							  생성과 사용이 분리되어 사용됨.
					environment:  환경변수 설정. Key는 대문자 권장.
					env_file: .env 파일로 환경변수 설정하고 한번에 사용.
					volumes: 영속성 위한 방법.
					         생성과 사용이 분리되어 사용됨.

					depends_on: 서비스 실행 순서 지정.
					working_dir: 서비스의 작업 디렉터리. 여러 명령어들의 기준위치 역할.
					healthcheck: 서비스의 상태 검사 ( 서비스 제공 여부 확인용 )
					restart: 서비스 재시작 정책 ( restart policy )
					
		---------------------------------------------------------------------------------			
	 2) image 속성.				
	    - 사용할 Docker 이미지 ( base image ),없으면 다운로드
		
		    ex. 
				services:
				  web: # 서비스명
					image: nginx:latest
					container_name: my-nginx   #  docker run --name my-nginx nginx
					
	 3) build 속성
	     - Dockerfile 파일 이용해서 직접 이미지 생성
		 
		    ex.
			     services:
				   backend:
				     build:
					   context: . | ./backend    # 이미지를 만들 때 필요한 파일등이 있는 경로 지정.
												   docker-compose.yaml 기준  
					   dockerfile: Dockerfile | ../my-Dockerfile  # 빌드에 사용할 Dockerfile 이름지정.
																	Dockerfile 파일인 경우 생략 가능.
					 image: springboot-app     # 생성할 이미지 명.     
					   
				
			 만약에 다음과 같은 디렉터리 구조라면?
			 
			    project/
				    - docker-compose.yaml              services:
					- backend/                 ==>         backend:
					    -Dockerfile                            build: 
						-...                                     context: ./backend
						                                       image: backend-app 
					- frontend/                            frontend:
                        -Dockerfile                            buiid:
						-....                                    context: ./frontend
						                                       image: front-app
															   
		  ----------------------------------------------------------------------------------
	  4) command 속성
	  
	     - 명령어, Dockerfile 의 CMD와 동일. 덮어쓰기 가능.	
		 - 컨테이너 실행시 shell 명령어를 사용할려면 /bin/sh -c '명령어' 
		 
		  ex. 
		       command: bundle exec thin -p 3000
	           command: /bin/sh -c 'echo "hello $$HOSTNAME"'
			   command: sh -c 'echo "hello $$HOSTNAME"'
	
	   5) entrypoint 속성 ( 고정 명령어용 )
	     
		  - 명령어. Dockerfile 의 entrypoint와 동일, 덮어쓰기 불가.
		  
		   ex.
		       entrypoint: /code/entrypoint.sh
			   
			   
		 6) ports 속성
		   
		    - 실제 포트 연결 기능 (**************)
			- 문자열로 지정하자. HOST:CONTAINER should always be specified as a (quoted) string, 
			                   to avoid conflicts with YAML base-60 float.
			
			ex. 
			
			   ports:
				  - "3000"
				  - "3000-3005"
				  - "8000:8000"
				  
		 7) expose 속성
		     - 포트 문서화 , Dockerfile의 EXPOSE 와 동일.
			   즉 실제 포트 연결 기능 없음 (***************)
			 - 문자열로 지정.
			 
			 ex. 
                expose:
				  - "3000"
				  - "8000"			  
				  
		  8) environment 속성
		     - 환경변수 설정. 
			 - Key는 대문자 권장.
			 
			 ex. 
			     environment:
				  RACK_ENV: development
				  DB_HOST=172.168.0.1
				  SHOW: "true"
				  
			  - 컨테이너 내부에서 사용방법
			      
				   $env
				   $printenv
				   
				   $echo $RACK_ENV
				   
			  - SpringBoot 에서 사용방법.
			  
			     spring:
				   profiles:
				     active: ${RACK_ENV:prod}
					 
		  9) env_file 속성 
    		  - .env 파일로 환경변수 설정하고 한번에 사용.
			  - environment 가 우선권이 높음.
			  
			  ex. 
				   #.env 파일내용
				   DB_HOST=localhost
				   DB_USER=root
				   BOOT_PROFILES=dev	
					
			       env_file: .env
				   
			   - 컨테이너 내부에서 사용방법
			      
				   $env
				   $printenv
				   
				   $echo $DB_HOST
				   
			  - SpringBoot 에서 사용방법.
			  
			     spring:
				   profiles:
				     active: ${BOOT_PROFILES:prod}	   
					 
		11) networks 속성
		  
		    - 기본적으로 docker-compose는 동일 네트워크로 자동으로 묶임.
			  따라서 서비스명으로 접근이 가능함.
			- 명시적으로 지정도 가능 ( 이유는 네트워크를 분리 목적)
			
			 ex.
			 
			 
			    networks:  # 네트워크 생성
				  - some-network
			      - other-network
			 
				services:
				  some-service:
					networks:   # 네트워크 사용
					  - some-network
					  - other-network
					  
					  
			 ex. front/backend/mysql
			 
			      
			      networks:  # 네트워크 생성
				  - db-net
			      - web-net
				  
				  services:
				     mysql:
					   image: mysql:8.3
					   ..
					   networks: # 네트워크 사용
					     - db-net
						 
				     backend:
					   image: springboot:4.5
					   ..
					   networks:  # 네트워크 사용
					     - db-net
						 
					 front:
					   image: vue.js:4.6
					   ..
					   networks: # 네트워크 사용
					     - web-net
		-----------------------------------------------------------
		12) volumes 속성
		   - 영속성 유지 목적.
		   
		    
			ex. 
				volumes:   # 볼륨 생성
				  db-data:
				  
				services:
				     mysql:
					   image: mysql:8.3
					   
					   volumes:   # 볼륨 사용
					     db-data:/var/lib/mysql
						 
					   networks: 
					     - db-net  
			 
			 
		13) depends_on 속성
		
		   - 서비스 순서 지정.
		   - 실제 db와 redis가 정상적으로 실행될때까지는 안 기다림.
		     따라서 healthcheck로 서비스 여부 확인필요.
		   
		    ex.
			      services:
					  web:
						build: .
						depends_on:  # web 보다 먼저 db와 redis 가 실행됨.
						  - db
						  - redis
					  redis:
						image: redis
						
					  db:
						image: mysql:8.3
		
	-----------------------------------------------------
	  14) healthcheck 속성.
	     
		  - 서비스가 정상인지 검사.
		  
		    ex.
			
			   healthcheck:
				  test: ["CMD", "mysqladmin", "ping",-h", "localhost"]
				  interval: 1m30s
				  timeout: 10s
				  retries: 3
				  start_period: 40s
				  start_interval: 5s
				  
			ex2.
			
			      ex.
			      services:
					  web:
						build: .
						depends_on:  # web 보다 먼저 db와 redis 가 실행됨.
						  - db
						  - redis
						  
						healthcheck:
						  test: ["CMD", "mysqladmin", "ping",-h", "localhost"]
						  interval: 1m30s
						  timeout: 10s
						  retries: 3
						  start_period: 40s
						  start_interval: 5s
				  
					  redis:
						image: redis
						
					  db:
						image: mysql:8.3
						
		-------------------------------------------
		15) restart 속성
		  
		    - 서비스가 종료된 경우, 이후에 재시작 정책임.
			
			
			ex. 
			        restart: "no"  # 기본, 자동 재시작 안함.
					restart: always # 항상 재시작
					restart: on-failure # 오류 발생되서 종료된 경우에만 재시작
					restart: on-failure:3  #  오류 종료 시 3번까지만 재시작.
					restart: unless-stopped # 사용자가 명시적으로 중지하지 않으면 계소 재시작.
					
6. Compose 관련 명령어

   1) 실행 명령어
   
    
	    docker compose up          # 포그라운드로 실행됨. ( 기존 이미지 이용 )
		docker compose up -d       # 백그라운드로 실행됨. ( 기존 이미지 이용 )
		docker compose up -build   # 백그라운드로 실행됨. ( 새로운 이미지 생성 )

        docker compose up 서비스명  # 특정 서비스만 실행
		
		
	2) 종료 명령어

       docker compose down      # 컨테이너 중지 + 삭제
	   docker compose down -v   # Volume 포함해서 삭제
	   
	   docker compose down --rmi # 이미지까지 삭제됨.
	   
	   docker compose down 서비스명 # 특정 서비스만 종료
	   
	 
	3) 상태 및 로그 
	
	   docker compose ps
	   docker compose logs
