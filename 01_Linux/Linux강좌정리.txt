		  서버(ubuntu)  <------------------------------------ 클라이언트(window)
		  


		  
		  a. 서버에서 공개키(public Key)와 개인키(private key)를 생성.
		  b. 서버에는 공개키(public key)를 저장하고
		     클라이언트에는 개인키(private key)저장.
			 
		  c. 클라이언트가 서버에 접속할 때 비밀번호 대신에 개인키를 이용해서 접속시도함.
		  d. 서버에서는 클라이언트가 제공한 개인키와 공개키를 이용해서 key pair 검증함.
		     맞으면 로그인성공, 틀리면 로그인 실패.

 1. 프롬프트와 홈디렉터리
 
   1)프롬프트( prompt ) 개념
     - 사용자의 명령을 기다리는 표시.
     - ubuntu의 프롬프트 기본은 다음과 같다.
	 
	   user1@ubuntu:~$
	   
	   user1: 사용자 계정
	   ubuntu: 호스트명  # cat /etc/hostname 에서 확인가능.
	   ~ : user1 사용자의 홈디렉터리 경로 의미.
	       /home/user1
		   
	    $: 일반 사용자에서 사용하는 쉘프롬프트
		   일반 사용자가 할수 있는 작업들.
		    - 프로그램실행.
		    - 파일생성
			- 자신만의 홈디렉터리(ex. /home/user1)안에서만 작업이 가능(******************)
			
		#: root(관리자) 사용하는 쉘프롬프트
		   roor 사용자가 할 수 있는 작업들.
		    - 시스템 전체 권한을 가져서 모든 작업들을 처리가능.
			- 사용자생성
			- 패키지 설치 ( apt install, apt remove 등)
			- 서비스 시작/종료
			
	- 프롬프트에 많은 정보를 얻을 수 있음.
       현재사용자.	
	   호스트명.
	   현재경로.
	   현재 쉘.
	   
	2) 쉘관련 정보 얻기
       -현재사용자 조회: whoami
	   -호스트정보:  hostname	
	   -현재 쉘정보: 환경변수에 쉘정보 저장. SHELL=쉘  ( 윈도우에서는 %JAVA_HOME% , Linux에서는 $SHELL )
	               echo $SHELL
				   /bin/bash (배시쉘)
				   
	   -프롬프트 포맷:  환경변수에 쉘정보 저장. PS1=프롬프트포맷
	                 echo $PS1
					  
					 변경가능. ( export PS1="변경값" )

 2. 일반사용자에서 관리자로 변경하는 방법.
 
   1) 한번만 관리자로 변경해서 실행 ( 초보자에게 권장 )
   
      문법: sudo 명령어
	 
	   ex.  sudo apt update
	        sudo apt install openssh-server
			
			
   2) root로 쉘 변경 ( $ -----> # )
   
      a. 현재 사용자 경로를 유지하고 관리자로 변경하는 방법.
	  
	  문법:   sudo -s ( sudo su 와 비슷 )
	  
	     root@ubuntu:/home/user1# pwd
         /home/user1

	     root@ubuntu:/home/user1# apt update  <== sudo 없이 실행가능.
		 
		 
	  b. root 계정으로 변경하는 방법.

       문법:   sudo su -	  
	   
	      root@ubuntu:~# pwd
          /root

	
		 
   3) root 계정 인증한 캐시 삭제.
   
      문법:  sudo -k

 3.  리눅스 명령어 메뉴얼 보기
 
    1) man 명령어 이용.
	
	  ex.  $ man ls
	  
	     - q 입력해서 빠져나오기
	     -화살표키 이용해서 위/아래로 이동
		 -g: 맨 위로가 가기.
		  G: 만 아래로 가기.
		 -page up/ page down 가능. ( Ctrl + B, Ctrl + F )
		 -검색어 찾기
		  / 입력하고 검색어 입력.
		  
		  ex.
		    /like     n: 다음내용 보여주기

14) 파일 및 디렉터리 복사

      문법:  
	        cp [옵션]  원본  대상(타겟)
		
	  특징:
	         원본 및 대상: 파일이거나 디렉터리가 될 수 있음.
			 원본:  여러개 지정 가능
			 
			 ex.
			 
			     cp  원본파일   타겟파일
				 cp  원본파일1  원본파일2 ..  타겟디렉터리
				 cp -r 디렉터리 원본파일1  원본파일2 ..  타겟디렉터리
				 
	  옵션: 
	  
	       -i  : interactive 가능.
		   -p  : 원본파일의 속성(mode,소유자,시간)까지 유지되어 복사됨.
		   -r  : 원본에 디렉터리가 있는 경우. recursive
		   
		
		실습:
		      cp /etc/passwd     ./users.txt  
			  cp /etc/passwd     ./logs2/users.txt  # 타겟에 복사될 디렉터리 포함가능.
			  
			  cp -i /etc/passwd     ./users.txt  # 덮어쓰기 전에 물어봄.
			  
			  cp   hello.txt   users.txt   first/   # 있으면 복사되고 없으면 오류출력됨.
			  
			  cp  -r log2 users.txt  first/  # 원본이 디렉터리인 경우에는 -r 옵션 필수.
			  
		실습2:  -p 실습방법
		
		      -users.txt 의 소유자를 확인하자. <== user1 이 소유자.
			  
			  -관리자 권한으로 복사
			  
			    sudo cp users.txt  u.txt  <== u.txt 의 소유자?  root 임.
				
				sudo cp -p users.txt  u2.txt  <== u2.txt 의 소유자?  user1 임.

19) 하드링크 ( hard link)

  -개념:  같은 inode 값을 갖는 다른 파일.
         /////////////////////////////
			inode ?
			- 파일(파일,디렉터리,장치,...)의 실제 저장되는 주소값 의미.
		 ///////////////////////////////
		 
  - 문법:
          ln  원본파일 대상파일(타겟)
		  
  - 특징:
        디렉터리 지정불가 ( 디렉터리는 동일한 주소값을 가질수 없기 때문)
		inode가 같으면 데이터도 동일.
		한쪽이 수정되면 다른쪽도 영향을 미침.
		한쪽이 삭제되면 수정과 다르게 다른쪽에는 영향이 없음.
		( 삭제의미는 inode 참조하는 링크를 삭제하는 것이다.)
		
  - 목적:
       백업용도( 하나가 삭제가 되고 나머지 유지 )
	   보안이슈 ( 중요한 파일명을 노출하지 않을 수 있음 )
	   
	   
	실습:
          echo "hello" > m.txt # 원본파일

		   ln m.txt  m_copy.txt # 하드링크
	   
	      ls -il  # -i 는 inode 확인
	      
			1060500 -rw-rw-r-- 2 user1 user1    6 May 28 14:23 m_copy.txt
			1060500 -rw-rw-r-- 2 user1 user1    6 May 28 14:23 m.txt

		  cat m.txt  m_copy.txt      # 내용이 똑같은지 확인.
		  
		   echo "world" >> m.txt # 원본파일 수정. append 
		   cat m.txt  m_copy.txt      # 내용이 똑같은지 확인.
		   
		   rm m.txt  # 원본 삭제. 하드링크 삭제 안됨(유지됨), 링크갯수가 1개로 줄어듬
           1060500 -rw-rw-r-- 1 user1 user1   12 May 28 14:27 m_copy.txt

        경로단축

		   rm m2_copy.txt  # 소프트링크 파일 삭제

23. 리다이렉션 ( redirection )
   ////////////////////////////////////
       #표준입력/표준출력/표준에러
			  
			  file /dev/stdin  # 0번 ( 표준입력) 자바의 System.in 동일
			  file /dev/stdout # 1번 (표준출력)  자바의 System.out.println 동일
			  file /dev/stderr # 2번 (표준에러)  자바의 System.err.println 동일
   //////////////////////////////////////

   동작: 명령어의 입출력의 방향을 바꾸는 방법.
        일반적으로 콘솔의 출력되는 방향을 파일로 출력되도록 방향을 바꿈.
		대상파일이 없으면 자동으로 생성됨.
		
	문법:  
	       명령어 > 파일            ( <  : 표준입력
		                            >, >> : 표준출력(정상출력)
											> 의미: 덮어쓰기
											>> 의미:추가(append)
                          		    2>  :표준에러(비정상,오류출력)
									
		ex.
		      		ls > file.txt  # 덮어쓰기,
					ifconfig >> ifconfig.txt  # 추가(append)
					ifconfig | grep  ether  > MAC.txt
					wc -l  < file.txt  # 입력 리다이렉션
					
					ls  text.txt   wrong.txt  2> error.txt  # ls실행했을 때 출력되는 오류를 저장.
					
					ls  text.txt   wrong.txt > success.txt  2> error.txt # ls 실행했을때 출력되는 정상출력과
					                                                       오류 출력을 분리해서 저장.
																		   
	실습>
      	    ls > file.txt # 덮어쓰기. 파일이 없으면 생성.
			
			ls >> file.txt  # 추가(append)
			
			
			ifconfig | grep  ether  > MAC.txt는
			
			wc -l  < file.txt   # file.txt 읽어서 라인수 출력
			
			# 정상출력과 에러출력 분리하기.
			
			  #1. 정상출력만 있는 경우
			    
				 ls file.txt  > out.txt
			
			  #2. 비정상출력만 있는 경우
			   
  			    ls wrong.txt > error.txt	# 오류가 났음에도 불구하고 표준출력(정상출력)인 > 사용했기 때문에 리다이렉션이 안됨.
				 ls: cannot access 'worng.txt': No such file or directory


                ls wrong.txt 2> error.txt   # 오류용 2> 사용했기 때문에 정상적으로 리다이렉션이 됨.
				
			#2. 정상출력과 비정상출력 모두 있는 경우
			
				==> 동작방식은 정상출력값은 out2.txt에 정상적으로 리다이렉션이 되고
				    오류출력값을 그냥 콘솔에 출력됨.
					
			      ls file.txt wrong.txt > out2.txt   
				  ls: cannot access 'worng.txt': No such file or directory
				  
				==> 동작방식은 오류출력값은 error2.txt에 정상적으로 리다이렉션이 되고
				    정상출력값을 그냥 콘솔에 출력됨.
				   ls file.txt wrong.txt 2> error2.txt  
                   file.txt

               ==> 동작방식은 오류출력값은 error3.txt에 정상적으로 리다이렉션이 되고
				    정상출력값도   out3.txt 에 정상적으로 리다이렉션 됨.
				ls file.txt wrong.txt > out3.txt 2> error3.txt

25. 사용자 관리

   1) 사용자 종류
   
     가. 일반 사용자.
	    - root 사용자를 제외한 나머지.
		- 권한이 없기 때문에 특정 디렉터리인 홈디렉터리에서만 작업이 가능.
		  ex. /home/user1
	 
	 나. root 사용자.
		- 어떤 경로,명령어 모두 작업이 가능.
		- 일반사용자와 분리해서 관리하기 위해서  /home 디렉터리가 아닌 /root 가 홈디렉터리로 관리됨.
		
   2) 사용자 정보 관리 파일
   
      가. 사용자 정보 파일
	      - /etc/passwd 에 저장.
		  - 총 7개의 요소로 구성됨.
	      
	  
	      ex. 
		      root:x:0:0:root:/root:/bin/bash
			  user1:x:1000:1000:user1:/home/user1:/bin/bash

			  구성요소:
			  user1 :  계정명
			  x     :  암호화된 비번, x 의미는 다른파일에 저장됨을 의미함.
			            /etc/shadow에 저장되어 있음.

			  1000:  계정ID ( UID )
			  1000:  그룹ID ( GID )
			  user1: 커맨트 ( 임의의값)
			  /home/user1 : 홈디렉터리
			  /bin/bash: 쉘
	  
	  나. 사용자 비번 파일
	      - /etc/shadow
		  
            구성요소:
			user1:$6$jdds1iRadhV285GL$MrYef3RoLbW.A8ZM63xBCsH9W6F6YLguXN/f9/L9von			
			
	3) 사용자 그룹
	
	  -개념: 여러 사용자들을 묶어서 관리하기 위한 방법.
	  -그룹정보:
	  
	       /etc/group 관리
	
	       ex.  cat /etc/group
		   
		        user1:x:1000:
				
				user1: 그룹명
				x: 암호화된 비번
				1000: 그룹ID ( GID )

       -그룹종류
	   
	      가. Primary Group
		    - 사용자의 기본그룹
			
			- 명령어:  id 사용자명
			
			   $id user1
			   uid=1000(user1) gid=1000(user1) 
			   groups=1000(user1), <== 기본그룹
			        4(adm),24(cdrom),27(sudo),30(dip),46(plugdev),100(users),114(lpadmin) <== 추가그룹

		  나. Secondary Group
		    - 사용자의 추가그룹
			
			-명령어: groups 사용자명
			  
			    $ groups user1
				user1 : user1 adm cdrom sudo dip plugdev users lpadmin
