	   카. pem (Privacy Enhanced Mail) 파일 이용.
	   
	    - 비밀번호 입력없이 로그인 가능한 방법임. 
		- 비대칭키를 활용하는 방법.
	   
	    - 전체 아키텍처
		
		  서버(ubuntu)  <------------------------------------ 클라이언트(window)
		  


		  
		  a. 서버에서 공개키(public Key)와 개인키(private key)를 생성.
		  b. 서버에는 공개키(public key)를 저장하고
		     클라이언트에는 개인키(private key)저장.
			 
		  c. 클라이언트가 서버에 접속할 때 비밀번호 대신에 개인키를 이용해서 접속시도함.
		  d. 서버에서는 클라이언트가 제공한 개인키와 공개키를 이용해서 key pair 검증함.
		     맞으면 로그인성공, 틀리면 로그인 실패.
			 
		# 작업하기
		
		 # ubuntu에서 작업하기
		   
		    1)공개키와 개인키 생성.
			
			 ssh-keygen  -q  -N  ""  -f  ubuntu_user1_key.pem
		 
			 ==> ubuntu에 다음과 같은 2개의 파일이 생성됨.
			     ubuntu_user1_key.pem      ( 개인키, 클라이언트인 윈도우에 저장) 
				 ubuntu_user1_key.pem.pub  ( 공개키, 서버에 저장 )
		 
		    
			2) 공개키를 지정된 파일에 덮어쓰기
			
			  cat ubuntu_user1_key.pem.pub > ~/.ssh/authorized_keys
			  
			  cat .ssh/authorized_keys
			  ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIPwhfK4Zvsnv/aJC6QRdQPv1QoimNVhaknRfzAprgK6R user1@ubuntu

            3) 공개키 파일의 권한을 낮춰야 됨.
			  
			   chmod 600 ~/.ssh/authorized_keys

 1. 프롬프트와 홈디렉터리
 
   1)프롬프트( prompt ) 개념
     - 사용자의 명령을 기다리는 표시.
     - ubuntu의 프롬프트 기본은 다음과 같다.
	 
	   user1@ubuntu:~$
	   
	   user1: 사용자 계정
	   ubuntu: 호스트명  # cat /etc/hostname 에서 확인가능.
	   ~ : user1 사용자의 홈디렉터리 경로 의미.
	       /home/user1
		   
	    $: 일반 사용자에서 사용하는 쉘프롬프트
		   일반 사용자가 할수 있는 작업들.
		    - 프로그램실행.
		    - 파일생성
			- 자신만의 홈디렉터리(ex. /home/user1)안에서만 작업이 가능(******************)
			
		#: root(관리자) 사용하는 쉘프롬프트
		   roor 사용자가 할 수 있는 작업들.
		    - 시스템 전체 권한을 가져서 모든 작업들을 처리가능.
			- 사용자생성
			- 패키지 설치 ( apt install, apt remove 등)
			- 서비스 시작/종료
			
	- 프롬프트에 많은 정보를 얻을 수 있음.
       현재사용자.	
	   호스트명.
	   현재경로.
	   현재 쉘.
	   
	2) 쉘관련 정보 얻기
       -현재사용자 조회: whoami
	   -호스트정보:  hostname	
	   -현재 쉘정보: 환경변수에 쉘정보 저장. SHELL=쉘  ( 윈도우에서는 %JAVA_HOME% , Linux에서는 $SHELL )
	               echo $SHELL
				   /bin/bash (배시쉘)
				   
	   -프롬프트 포맷:  환경변수에 쉘정보 저장. PS1=프롬프트포맷
	                 echo $PS1
					  
					 변경가능. ( export PS1="변경값" )

 2. 일반사용자에서 관리자로 변경하는 방법.
 
   1) 한번만 관리자로 변경해서 실행 ( 초보자에게 권장 )
   
      문법: sudo 명령어
	 
	   ex.  sudo apt update
	        sudo apt install openssh-server
			
			
   2) root로 쉘 변경 ( $ -----> # )
   
      a. 현재 사용자 경로를 유지하고 관리자로 변경하는 방법.
	  
	  문법:   sudo -s ( sudo su 와 비슷 )
	  
	     root@ubuntu:/home/user1# pwd
         /home/user1

	     root@ubuntu:/home/user1# apt update  <== sudo 없이 실행가능.
		 
		 
	  b. root 계정으로 변경하는 방법.

       문법:   sudo su -	  
	   
	      root@ubuntu:~# pwd
          /root

	
		 
   3) root 계정 인증한 캐시 삭제.
   
      문법:  sudo -k

 3.  리눅스 명령어 메뉴얼 보기
 
    1) man 명령어 이용.
	
	  ex.  $ man ls
	  
	     - q 입력해서 빠져나오기
	     -화살표키 이용해서 위/아래로 이동
		 -g: 맨 위로가 가기.
		  G: 만 아래로 가기.
		 -page up/ page down 가능. ( Ctrl + B, Ctrl + F )
		 -검색어 찾기
		  / 입력하고 검색어 입력.
		  
		  ex.

14) 파일 및 디렉터리 복사

      문법:  
	        cp [옵션]  원본  대상(타겟)
		
	  특징:
	         원본 및 대상: 파일이거나 디렉터리가 될 수 있음.
			 원본:  여러개 지정 가능
			 
			 ex.
			 
			     cp  원본파일   타겟파일
				 cp  원본파일1  원본파일2 ..  타겟디렉터리
				 cp -r 디렉터리 원본파일1  원본파일2 ..  타겟디렉터리
				 
	  옵션: 
	  
	       -i  : interactive 가능.
		   -p  : 원본파일의 속성(mode,소유자,시간)까지 유지되어 복사됨.
		   -r  : 원본에 디렉터리가 있는 경우. recursive
		   
		
		실습:
		      cp /etc/passwd     ./users.txt  
			  cp /etc/passwd     ./logs2/users.txt  # 타겟에 복사될 디렉터리 포함가능.
			  
			  cp -i /etc/passwd     ./users.txt  # 덮어쓰기 전에 물어봄.
			  
			  cp   hello.txt   users.txt   first/   # 있으면 복사되고 없으면 오류출력됨.
			  
			  cp  -r log2 users.txt  first/  # 원본이 디렉터리인 경우에는 -r 옵션 필수.
			  
		실습2:  -p 실습방법
		
		      -users.txt 의 소유자를 확인하자. <== user1 이 소유자.
			  
			  -관리자 권한으로 복사
			  
			    sudo cp users.txt  u.txt  <== u.txt 의 소유자?  root 임.
				
				sudo cp -p users.txt  u2.txt  <== u2.txt 의 소유자?  user1 임.

19) 하드링크 ( hard link)

  -개념:  같은 inode 값을 갖는 다른 파일.
         /////////////////////////////
			inode ?
			- 파일(파일,디렉터리,장치,...)의 실제 저장되는 주소값 의미.
		 ///////////////////////////////
		 
  - 문법:
          ln  원본파일 대상파일(타겟)
		  
  - 특징:
        디렉터리 지정불가 ( 디렉터리는 동일한 주소값을 가질수 없기 때문)
		inode가 같으면 데이터도 동일.
		한쪽이 수정되면 다른쪽도 영향을 미침.
		한쪽이 삭제되면 수정과 다르게 다른쪽에는 영향이 없음.
		( 삭제의미는 inode 참조하는 링크를 삭제하는 것이다.)
		
  - 목적:
       백업용도( 하나가 삭제가 되고 나머지 유지 )
	   보안이슈 ( 중요한 파일명을 노출하지 않을 수 있음 )
	   
	   
	실습:
          echo "hello" > m.txt # 원본파일

		   ln m.txt  m_copy.txt # 하드링크
	   
	      ls -il  # -i 는 inode 확인
	      
			1060500 -rw-rw-r-- 2 user1 user1    6 May 28 14:23 m_copy.txt
			1060500 -rw-rw-r-- 2 user1 user1    6 May 28 14:23 m.txt

		  cat m.txt  m_copy.txt      # 내용이 똑같은지 확인.
		  
		   echo "world" >> m.txt # 원본파일 수정. append 
		   cat m.txt  m_copy.txt      # 내용이 똑같은지 확인.
		   
		   rm m.txt  # 원본 삭제. 하드링크 삭제 안됨(유지됨), 링크갯수가 1개로 줄어듬
           1060500 -rw-rw-r-- 1 user1 user1   12 May 28 14:27 m_copy.txt

   목적:
        경로단축
		
	  실습:
	  
	       echo "hello" > m2.txt # 원본파일

	      1060644 lrwxrwxrwx 1 user1 user1    6 May 28 14:44 m2_copy.txt -> m2.txt

		   rm m2.txt  # 원본 삭제.
		   
		    ls -il  # 깨져서 출력됨. 해결: 소프트링크 파일 삭제
			
		   rm m2_copy.txt  # 소프트링크 파일 삭제

		    mkdir temp

			ls -al temp

			ls -al temp2

23. 리다이렉션 ( redirection )
   ////////////////////////////////////
       #표준입력/표준출력/표준에러
			  
			  file /dev/stdin  # 0번 ( 표준입력) 자바의 System.in 동일
			  file /dev/stdout # 1번 (표준출력)  자바의 System.out.println 동일
			  file /dev/stderr # 2번 (표준에러)  자바의 System.err.println 동일
   //////////////////////////////////////

   동작: 명령어의 입출력의 방향을 바꾸는 방법.
        일반적으로 콘솔의 출력되는 방향을 파일로 출력되도록 방향을 바꿈.
		대상파일이 없으면 자동으로 생성됨.
		
	문법:  
	       명령어 > 파일            ( <  : 표준입력
		                            >, >> : 표준출력(정상출력)
											> 의미: 덮어쓰기
											>> 의미:추가(append)
                          		    2>  :표준에러(비정상,오류출력)
									
		ex.
		      		ls > file.txt  # 덮어쓰기,
					ifconfig >> ifconfig.txt  # 추가(append)
					ifconfig | grep  ether  > MAC.txt
					wc -l  < file.txt  # 입력 리다이렉션
					
					ls  text.txt   wrong.txt  2> error.txt  # ls실행했을 때 출력되는 오류를 저장.
					
					ls  text.txt   wrong.txt > success.txt  2> error.txt # ls 실행했을때 출력되는 정상출력과
					                                                       오류 출력을 분리해서 저장.
																		   
	실습>
      	    ls > file.txt # 덮어쓰기. 파일이 없으면 생성.
			
			ls >> file.txt  # 추가(append)
			
			
			ifconfig | grep  ether  > MAC.txt는
			
			wc -l  < file.txt   # file.txt 읽어서 라인수 출력
			
			# 정상출력과 에러출력 분리하기.
			
			  #1. 정상출력만 있는 경우
			    
				 ls file.txt  > out.txt
			
			  #2. 비정상출력만 있는 경우
			   
  			    ls wrong.txt > error.txt	# 오류가 났음에도 불구하고 표준출력(정상출력)인 > 사용했기 때문에 리다이렉션이 안됨.
				 ls: cannot access 'worng.txt': No such file or directory


                ls wrong.txt 2> error.txt   # 오류용 2> 사용했기 때문에 정상적으로 리다이렉션이 됨.
				
			#2. 정상출력과 비정상출력 모두 있는 경우
			
				==> 동작방식은 정상출력값은 out2.txt에 정상적으로 리다이렉션이 되고
				    오류출력값을 그냥 콘솔에 출력됨.
					
			      ls file.txt wrong.txt > out2.txt   
				  ls: cannot access 'worng.txt': No such file or directory
				  
				==> 동작방식은 오류출력값은 error2.txt에 정상적으로 리다이렉션이 되고
				    정상출력값을 그냥 콘솔에 출력됨.
				   ls file.txt wrong.txt 2> error2.txt  
                   file.txt

               ==> 동작방식은 오류출력값은 error3.txt에 정상적으로 리다이렉션이 되고
				    정상출력값도   out3.txt 에 정상적으로 리다이렉션 됨.
				ls file.txt wrong.txt > out3.txt 2> error3.txt

26.  파일 접근 권한 관리

   1) 개념
    - 파일(디렉터리 포함)에 무단으로 접근하는 것을 방지하기 위한 방법.
	- 3가지로 권한으로 관리가능. ( 읽기/쓰기/실행. rwx )
	
   2) 3가지 권한 
     
	 -읽기권한: r 로 표기 (read)
	 -쓰기권한: w 로 표기 (write)
	 -실행권한: x 로 표가 (execute)
	 -아무권한없음: - 로 표기
	 
	 ex. ls -al
	 
	    rw-       r--      r--
	
      소유자권한  그룹권한   other권한
	  
	  
  3) 파일접근권한 변경1 - 기호모드 이용
      
	    가. 사용자 카테고리 ( 권한을 부여하거나 취소할 대상을 정할 때 사용 )
		    
			u : 파일소유자의미.
			g : 파일 소유자가 속한 그룹의미
			o : 기타 사용자.
			a : 모든 사용자
     		
		나. 연산자 기호 ( 권한을 부여하거나 취소할 때 사용)
		
		    +: 권한부여
			-: 권한취소
			=: 명시적으로 권한할당
			
		다. 권한종류
           r: 읽기권한
		  w: 쓰기 권한
		  x: 실행권한
	 
		 ex. 
		      u+w   : 파일소유자에게 쓰기 권한 부여.
			  u+rwx : 파일소유자에게 읽기,쓰기,실행 권한 부여.
			  
			  g-w :   파일소유자가 속한그룹에서 쓰기권한 취소
			  o+r :   기타 사용자에게 읽기 권한 부여.
			  u+x, o+rwx :  파일소유자에게는 실행권한 부여하고  기타사용자에게 읽기,쓰기,실행 권한 부여
			  a+x:       :  모든 사용자에게 실행권한 부여.
			  u=rxw, o-w:  : 파일소유자는 읽기,쓰기,실행 권한 부여되고 기타 사용자는 쓰기 권한 취소
			  ug=rwx  :   u=rwx, g=rwx 와 동일.
			  o=       :   기타 사용자 권한 모두 취소
       
	    라. 명령어
		
		문법:
		 
		     chmod u+w 파일
  
		  실습>
			    touch exam.txt
		       
			   #권한 초기화
			   chmod 000 exam.txt
			   
			   chmod u+w  exam.txt
			   
			    chmod u+rwx  exam.txt
				
               chmod o+r  exam.txt 
  
				chmod ug=rwx  exam.txt
				
				chmod u=rwx exam.txt
				
				chmod g= exam.txt 
				
				
				chmod ug=rwx, o=  exam.txt ( 오류발생)
				chmod ug=rwx,o=  exam.txt ( 띄어쓰기 안됨 )
				
				
  3) 파일접근권한 변경2 - 숫자 이용  (*****************)
  
      -개념: 권한이 있으면 1, 없으면 0으로 표기하고 나중에 10진수로 표기.
	  
	    ex.
			r: r--:100 ==>4
		    w: -w-: 010 ==> 2
			x: --x: 001  ==> 1
		
			원본: rwxr--r-x
				
		     rwx: 111 표기 : 7
				            2진수를 10진수로 표기법: 
							

			 r--: 100 표기 : 4
			 
			 r-x: 101 표기   5
			 
			 
			 => chmod 745 exam.txt==>  rwxr--r-x
			   
			    chmod 641 exam.txt==>  rw-r----x
				
				chmod 600 exam.txt==>  rw-------

	 -PID가 작을수록 중요한 프로세스임.
	 -포그라운드(foreground) 및 백그라운드(background) 실행가능.
	 
  3) 프로세스 보기
   
    문법:
	      ps   # 현재 터미널에서 실행한 프로세스 정보만 출력.
		 
		  ps -ef  # 모든 프로세스 정보 출력
		  
		   실행결과는 다음과 같다.
		   UID          PID    PPID  C STIME TTY          TIME CMD
		   user1     151459    2943 99 15:41 pts/0    00:00:00 ps -ef

		  user1: 프로세스를 실행한 사용자.
		  151459: PID ( 프로세스 아이디 )
		  2943 :  PPID ( 부모 프로세스 아이디 )
		  99:  CPU 사용류
		  15:41: 시작시간
		  pts/0 : 터미널
		  00:00:00: 사용시간
		  ps -ef: 실행명령어
		  
		 
		   ps -ef | grep java # 외우기 (***************)
		   
	-주요 명령어
	  top # 현재 실행중인프로세스에대한정보를주기적으로출력.        
	▪ fg # 백그라운드작업을다시foreground로 실행
	▪ bg # 멈춰놓은작업을다시background로실행
	▪ ctrl + z    # 프로세스 중지
	▪ ctrl + c    # 프로세스 종료
	▪ kill  pid # 프로세스에종료신호보냄
	▪ kill -9  pid # 강제 종료
      & : 백그라운드로 실행
  
      실습1>
	         top  # 현재 실행중인프로세스

	  실습3> background 실행  및 종료
	  
	        sleep 50 &  # background 실행
			
			jobs         # 백그라운드/중지된 프로세스 확인
			ps
			ps -ef | grep sleep 
	 
	        kill -9 PID
			
	  실습4> foreground-->  background --> foreground
	  
	        sleep 100    # foreground
			 ctrl + z    # 프로세스 중지
			jobs         # 백그라운드/중지된 프로세스 확인
			
			
			bg %1        #[1] 작업을 의미
			jobs
			
			fg %1    
			ctrl + c    # 프로세스 종료

31. 쉘(shell)

  1)개념

  2) 구조
  
     응용프로그램 ( vim, ... )
     --------------------------
     쉘(shell)
    ----------------------------------
     리눅스커널 ( 프로세스 관리, 메모리 관리 등)
    --------
      h/W
	  
 3) 쉘 종류
    
	cat /etc/shells  # 현재 리눅스에 설치된 쉘목록
	
	  # /etc/shells: valid login shells
	  
		/bin/sh          # 표준 (기능이 떨어짐) 
		/usr/bin/sh      # /bin/sh의 링크
		
		/bin/bash		 # 현재 쉘 ( sh보다 기능이 많음 )
					       ex. echo {1..10}, arr=(1,2,3) 등 지원됨.
						   
		/usr/bin/bash    # /bin/bash 링크
		
		/bin/rbash       # 기능이 제한된 쉘
		/usr/bin/rbash
		
		/usr/bin/dash    # 매우 가볍움. 속도가 빠름. ( bash 기능지원안됨 )

32. 쉘(shell) 스크립트

   1)개념
      -실행가능한 텍스트 파일 의미.
	  - *.sh 파일형식을 사용.
	  -프로그램언어가 가진 구성요소 포함
	   ex. 변수, 연산자, 제어문, 함수 등
	  
	  -반드시 실행권한이 필요함.
	   ex. rwx 
	    
		 chmod 700 test.sh
		 
   2)문법
    
	 - 반드시 첫라인에 다음과 설정해야 됨.
	  
	    #!/bin/bash   <== 실행할 쉘의 경로를 지정하는 것임.
   
	    문장1
		문장2
		..
		
		
   3)실행하는 방법. 		
     - 권한 변경
	   chmod 700 test.sh
	   
	  $./test.sh    #  그냥 test.sh 는 안됨.
	 
	  $ bash test.sh
	  $ source test.sh

34. Special Variable

   1)개념:  쉘 내부에 미리 정의된 변수 의미. ( 내장 변수 )
   
   2)종류:
   
        $0 : 파일명
		$1,$2... : 10부터는 중괄호지정한다. ex. ${10},${11}
		$# : 스크립트에전달된인자의갯수
		$@ : 전달된모든인자전체( 개별항목으로유지)
		$* : 전달된모든인자전체( 모든인자를하나의문자열로합침)
		$$ : 현재실행중인쉘또는스크립트의PID
		$? : 바로직전에실행한명령어의결과코드(0:성공, 이외값:실패)
		$! : 가장최근에백그라운드로실행한프로세스PID
   
   
       실습1> test3.sh
	   
	     
			#!/bin/bash

			echo "file: $0"
			echo "arg1: $1"
			echo "arg2: $2"
			echo "$#: $#"     # 인자 갯수
			echo "$@: $@"     # 인자 모두 전달
			echo "$*: $*"     # 인자 모두 전달
			echo "$$: $$"     # 현재 실행주인 스크립트 PID
			
			chmod 700 test3.sh
			./test3.sh   one two 
			
			
		실습2> 
		     가. 명령어를 실행
			    ls /tmp  # 존재하는 디렉터리 . 성공
				echo "$?" # 0 , 즉 이전에 실행했던 ls /tmp가 성공했음
				
				ls /temp  # 존재하지 않는 디렉터리 . 실패
			   echo "$?"  # 0이 아닌값 출력 , 즉 이전에 실행했던 ls /tmep가 실패했음

35. 연산자

  1) 비교 연산자 ( 수치 데이터만 사용됨 )
  
     -eq:   같냐
	 -ne:   같지 않냐
	 -gt:   크냐
	 -ge:   크거나 같냐
	 -lt:   작냐
	 -le:   작거나 같냐
   
     조건식 문법:  
	         [[ 조건식 ]]   # [ 조건식 ]은 과거문법
			 
			 ex. 
			     n=10
				 [[ $n -eq 10 ]] # 성공/실패
				 echo "result: $?"
   
   2) 문자열 비교
    
	   =, == : 같냐
	   !=    : 같지 않냐
	   -z    : 길이가 0이냐
	   -n    : 길이가 0이 아니냐
	   
	   
	         ex. 
			       name=hello  # "hello" 동일
				 
				  [[ $name == "hello" ]] # 같냐?
				   echo "result: $?"
				 
				 [[ $name != "hello" ]] # 같지 않냐
				   echo "result: $?"
				   
				  [[ -z $name  ]] # 길이가 0 이냐
					echo "result: $?"

	              [[ -n $name  ]] # 길이가 0 이 아니냐
				   echo "result: $?"  
			
					# 패턴 매칭 가능
			       [[ $name == h* ]] #  h로 시작하냐?
				   [[ $name == *o ]] #  o로 끝나냐?
				   echo "result: $?"
		
   3) 논리 연산자

          && : 그리고
          || : or 		  
		  !  : 부정
		  
		      ex.  n=8
			      [[ $n -eq 10 || $n -lt 10 ]]
				  [[ $n -eq 10 && $n -lt 10 ]]
				  [[ !($n -eq 10) ]]
				  
 4) 산술 연산자
 
       +,-,*,/,%
	   
	   계산 시: $(( 연산 ))
	   
	   ex.
	       a=10
			b=3
			echo $((a + b))
			echo $((a - b))
			echo $((a * b))
			echo $((a / b))
			echo $((a % b))
			
 5) 증감 연산자
  
       ++, --
	   전치/후치 적용됨
       계산 시: $(( 연산 ))
	   
	   ex.     n=10
			   n2=$((++n))
			   echo "$n, $n2"
			   
			   x=10
			   x2=$((x++))
			   echo "$x, $x2"
	   
  6) 파일 검사 연산자.
   
  
	 -e:  파일/디렉터리가존재여부
     -f :  일반파일( 텍스트, 로그등)
     -d  : 디렉터리여부
	 -r  : 읽기 가능 여부
     -w  : 쓰기 가능 여부
     -s  : 크기가0보다크다
	 -L  : 심보릭링크여부
	 
	 
	    ex.   [[ -e test.sh ]] # test.sh 파일이 있냐
			   echo $?
			   
			   [[ -d tmp/ ]]   #  tmp가 디렉터리냐?
			   echo $?
			   
			   [[ -s test.sh ]]   # 파일 크기가0보다 크냐?
			   echo $?
			   
			   
			   ln -s test.sh  test_copy.sh
			   [[ -L test_copy.sh ]]   #  test_copy.sh가 심볼릭 링크냐?
			   echo $?
