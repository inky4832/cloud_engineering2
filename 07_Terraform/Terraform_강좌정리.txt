	   - terraform destroy   : Terraform이 관리하는 모든 리소스를 삭제.

  1. 데이터 종류 
  
    https://developer.hashicorp.com/terraform/language/expressions/types

     1) Primitive types
	    
		가. string
		   ex.  "hello"
		나. number
		   ex.  100,   3.14
		다. bool 
		   ex. true/false 
	 
	 
	 2) Collection types (  complex types, structural types )

        라. list ( 순서있고 중복 허용 가능 )
		   ex.   ["us-west-1a", "us-west-1c"]
		   
		마. set   ( 순서없고 중복 불가)
		https://developer.hashicorp.com/terraform/language/expressions/types#sets 참고해서 사용하자.

		바. map 
		 ex. {name = "Mabel", age = 52}
		      또는
			  {name : "Mabel", age : 52}
		
	3) Special vaue 
	
	   사. null

8. Resouce Lifecycle 
/////////////////////////////////////			 

https://developer.hashicorp.com/terraform/language/block/resource#lifecycle

   1.개념 
     Resource의 생성/수정/삭제 방식을 제어 가능 
	 

   2. 문법
   
     resource "타입" "라벨"{
	   
	    ...
		lifecycle{
			create_before_destroy=true
			prevent_destroy = true 
		    ignore_changes = [ <attribute> ]
			replace_triggered_by=[ 의존성 ]
		}
	}	
	
	
	 가. create_before_destroy=true|false
	   - 기본적으로 resource 교체할 경우 동작 방식은 다음과 같다. 
	     기본적으로 이전 리소스(A)를 먼저 삭제하고 나중에 새로운 리소스(A2)가  생성됨. 
		 만약 서비스중이라면 문제가 심각해짐.
		 create_before_destroy=true 지정하면 A2가 먼저 생성되고 나중에 A가 삭제됨.
		 
	 나. prevent_destroy = true 
	   - terraform destroy 하면 Terraform이 관리했던 모든 리소스가 삭제됨. 
	     중요한 Resource의 삭제방지하는 방법임.
	 
	
	다. ignore_changes = [ <attribute> ]
	  -  Terraform이 관리하는 리소스의 attribute 값을 외부에서 변경 시, 해당 변경사항을 Terraform이 무시하는 기능 
	  
	    ex.
		  lifecycle{
		      ignore_changes =[tags, ....]
	      }
	   
	
	라. replace_triggered_by=[ 의존성 ]
	
	  - (EC2의 )직접적인 Argument 변경 없이도  의존성이 있는 다른 Resource(Subnet)가 변경되면
        현재 Resource(EC2)가 교체하도록 지정가능.	  
	
	   ex. 
	   
	       lifecycle{
		      replace_triggered_by =[ aws_subnet.public-inky4832.id]
	      }
